# doc-writer 规则明细

## 1. 生命周期规则

| 文档 | 要求 |
|---|---|
| 需求 | 长期保留;清单 + 独立文件;状态:未开始/设计中/已落地 |
| 架构 | 施工完成后在标题/开头标记"已施工,归档可删";**不主动删除**,用户要删才删;不要求持续维护 |
| 业务说明书(Workflow) | 沉淀,必须维护;实现与说明书不一致视为文档过期,施工后立即回填 |
| 简报 | 按需;由大到小(主题→细节→结论→下一步) |
| 说明四件套 | 结构性变更后同步更新;底部 `## 变更记录` |

## 2. 编号与命名

- 三个空间各自从 01 独立编号(Workflow / 架构 / 需求),互不冲突。
- 编号是引用锚点:重命名 = 同步更新所有引用它的文档(用 Grep 搜旧文件名)。
- 文件:中文名;目录:中文;代码标识符:英文。

## 3. 口吻

- 全中文;开头 3 行内"一句话"。
- 表格表达对比;诚实评估硬要求(代价/边界/取舍/不做什么)。
- 引用文档相对链接;引用代码 `[文件.kt](路径#L行号)`。

## 4. 分类边界(易混场景)

| 内容 | 归属 | 原因 |
|---|---|---|
| 设备连接流程(扫描→连接→绑定) | Workflow | 业务视角 |
| 原生扫描替换 / 端口挂载 / 词汇统一 | 架构 | 跨业务结构决策 |
| "数据库信息上传服务器" | 需求 | 用户要什么 |
| 项目树 / 拓扑 / 词汇 / 演进史 | 说明 | 静态快照 |
| 周报 / 阶段汇报 | 简报 | 周期性 |

## 5. 代码-文档联动清单(重构后必查)

| 代码变更 | 受影响文档 |
|---|---|
| 词汇/契约变化 | 词汇表、README、所有含该词汇的文档 |
| 端口能力变化 | 拓扑(能力表)、项目树(适配器层) |
| 新业务/新包 | 项目树、演进史、Workflow 新说明书 |
| 结构性重构 | 拓扑、演进史、架构(新设计) |
| 行为修复 | Workflow 对应说明书 + 变更记录 |

## 6. 禁止事项

- 禁止跳过对话直接写设计(阶段 1 不写文档)。
- 禁止架构文档进 Workflow/,禁止 Workflow 进架构。
- 禁止残留已删除词汇(Command/Result/CommandPort)。
- 禁止删除变更记录历史(只追加)。
- 禁止施工后不更新业务说明书。
- 禁止不更新索引。
