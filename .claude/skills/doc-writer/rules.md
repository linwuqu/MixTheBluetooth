# doc-writer 规则明细

## 1. 命名规则

| 对象 | 规则 | 示例 |
|---|---|---|
| 目录 | 中文、语义化 | `Workflow/` `架构/` `需求/` `简报/` `说明/` |
| 设计文档文件 | `NN-中文名.md`(NN 沿用历史编号,不重排) | `02-设备连接.md` |
| 需求文件 | `NN-需求名.md` | `01-数据上云.md` |
| 简报文件 | `YYYY-MM-DD-主题.md` | `2026-07-24-第二次汇报.md` |
| 说明文件 | 固定四件套名 | `项目树.md` `拓扑.md` `词汇表.md` `演进史.md` |
| 代码标识符 | 英文(不受本文档体系约束) | — |

## 2. 编号规则

- 编号唯一且不因迁移重排(历史编号是引用锚点)。
- 新文档取"当前目录最大编号 + 1";业务编号与架构编号**各自独立**(见 Workflow/CONTENT 注)。
- 需求编号:清单内 `00-NN`,拆出后 `NN-需求名.md`。

## 3. 口吻规则

- 全中文;代码/词汇保留英文原样。
- 每个文档开头 3 行内必须给出"一句话"。
- 用表格表达对比(现状 vs 目标、职责 vs 不做什么)。
- **诚实评估是硬要求**:必须写代价/边界/取舍,禁止只写优点。
- 引用文档用相对链接 `[00-父子编排器](../架构/00-父子编排器.md)`,引用代码用 `[文件名.kt](相对路径#L行号)`。

## 4. 分类边界(易混场景)

| 内容 | 归属 | 原因 |
|---|---|---|
| 设备连接流程(扫描→连接→绑定) | Workflow | 具体业务的流程 |
| 原生扫描替换(BluetoothLeScanner) | 架构 | 能力层结构决策 |
| 端口挂载 / 词汇统一 | 架构 | 跨业务契约 |
| "数据库信息上传服务器" | 需求 | 用户要什么 |
| 项目树 / 拓扑 / 词汇 / 演进史 | 说明 | 静态快照 |
| 周报 / 阶段汇报 | 简报 | 周期性汇报 |

## 5. 代码-文档联动清单(重构后必查)

| 代码变更 | 受影响文档 |
|---|---|
| 词汇/契约变化(如删 CommandPort) | 词汇表、README 总蓝图、所有含该词汇的设计文档 |
| 端口能力变化 | 拓扑(能力端口表)、项目树(适配器层) |
| 新业务/新包 | 项目树、演进史、对应业务文档 |
| 结构性重构 | 拓扑、演进史(新阶段一节) |
| 行为修复 | 对应业务/架构文档的落地状态与变更记录 |

## 6. 禁止事项

- 禁止把架构文档写进 Workflow/(目录语义是业务)。
- 禁止文档中残留已删除词汇(Command/Result/CommandPort)。
- 禁止删除变更记录历史(只追加)。
- 禁止为了省事不更新索引。
