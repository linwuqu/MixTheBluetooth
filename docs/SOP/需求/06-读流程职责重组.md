# 06-读流程职责重组(状态机收缩 + 监听器接管)

## 0. 一句话

Cgm 读缓存流程的状态机混入了连接生命周期、数据终结符、重试静默、空闲心跳四类本不该由转移表负责的事,导致状态轮转低效、卡住不可见、重连整段重做;改为"监听器接管四件事、状态机收缩为任务生命周期"的两层职责结构。

## 1. 原始诉求

用户对 CgmReadDecision 的原始描述(2026-08-21 对话,节选原文):

1. "Failed Reconnecting Error Stopped的区分确实是有意义的 但是在状态机中间轮转感觉并不是一个很高效的行为"
2. "onRecords 中 endReached这个过程是轮询的 以上两点都反映出了其实在这里用状态机可能并不是很清晰 或许转换一个思维做成小的listener 类似于蓝牙一样"
3. "数据长时间收不到 但是因为重试的缘故或者Transition静默的缘故一直卡住"
4. "突然断连 再次连接时 状态机应该继续任务而不是整个重做"
5. "在此之上应该建立一个合理的监听 然后适当的将状态机缩小 同时两者需要进行配合"

## 2. 拆解与边界

| 拆解项 | 说明 | 是否本期做 |
|---|---|---|
| 监听器接管连接生命周期 | 断线/重连成功/重连失败不进状态机,由协调器挂起/恢复任务 | 是 |
| 监听器接管数据终结符 | END 检测上移到解析/适配层,状态机不再扫描数据、不再携带累积 | 是 |
| 监听器接管重试可见性 | 每次重读回调 onRetry(原因 + 次数),禁止静默重试 | 是 |
| 监听器接管空闲心跳 | 停滞钟跨重试不清零,堵住"重试重启超时窗"的卡死 | 是 |
| 状态机收缩 | 删 Sending/Reconnecting/Error + ResetError 仪式,保留任务生命周期 + 重试预算 + 双闸门 | 是 |
| 重连继续语义 | 任务身份保留、UI 数据保留;数据因协议全量回放必然重读(恢复重读不消耗预算) | 是 |
| 短命令状态机 | 对时/删除流程不受影响,不拆 | 否 |

## 3. 涉及面

- 业务域:读缓存(发 ALL → 收数据 → 校验 → 落盘 → 删缓存)
- 端口能力:port/cgm 契约(观察事件语义 + 本地落盘直调)、port/adapter 终结符检测上移
- 新增:协调器(translation/cgm)与停滞钟;扩展 StopReason 枚举
