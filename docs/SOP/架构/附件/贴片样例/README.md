# 贴片样例码

开发联调用的 Data Matrix 样例。**不是生产码**——没有签名，字段值都是 demo。

配套设计见 [13-贴片扫码绑定.md](../../13-贴片扫码绑定.md) 的 D1。

## 怎么用

**手机上扫（推荐）**：电脑上双击 `扫码页.html`，浏览器里按 <kbd>1</kbd>–<kbd>6</kbd> 或 <kbd>←</kbd><kbd>→</kbd> 切换，码会撑满窗口。然后拿手机对着屏幕扫。

**验多码点选**：同一个页面按 <kbd>0</kbd>（或点「六枚同屏」）切成 3×2 一屏六枚。此时 App 应当给每枚码各画一个框，且**不自动绑定**——点哪枚绑哪枚，点空白处只对焦。切回单枚视图（<kbd>1</kbd>–<kbd>6</kbd>）后又恢复"对准就自动绑"。

**打印扫**：打印 `贴片样例码.png`（一页六枚，两列三行）。

**单张投屏**：`投屏A.png` … `投屏F.png`，一张一枚，四周留白，用系统看图工具全屏打开也行。

## 文件

| 文件 | 说明 |
|---|---|
| `扫码页.html` | 六枚轮播 + 一屏六枚两种视图，码已内嵌成 data URI，**单文件、离线可用**，拷到别的机器上也能开 |
| `投屏A..F.png` | 一张一枚，864² 像素，超屏时浏览器/看图工具缩放后仍清晰（无插值） |
| `贴片样例码.png` | 打印页，一页六枚 |
| `Gen.java` | 生成器，改 `SAMPLES` 数组即可增删样例；**跑完自带回读验证** |

## 六枚分别验什么

前三枚该成功，后三枚该被拒绝——错误路径也得说得出原因，不然真机上分不清是"没扫到"还是"识别了但拒了"。

| 样例 | 码里是什么 | 预期 |
|---|---|---|
| A | `CGPATCH/1\|patchId=550e8400-…` | 绑定成功，单元标题右侧出现「贴片 550e8400」 |
| B | `…patchId=7c9e6679-…` | 变成「贴片 7c9e6679 · 共 2 枚」 |
| C | `…patchId=3f2504e0-…` | 变成「共 3 枚」 |
| D | 普通文本 `HELLO-DEMO-123456` | 扫码页不关，底部红条：「这不是贴片码」 |
| E | `CGPATCH/2\|…`（版本号不认识） | 「贴片码版本 2 暂不支持，当前 App 只认 1」 |
| F | `CGPATCH/1\|model=1\|lot=…`（缺 patchId） | 「贴片码里没有编号」 |

A/B/C 的 `patchId` 前 8 位互不相同（`550e8400` / `7c9e6679` / `3f2504e0`），扫完看短号就能分辨是哪一枚。

## 码里是什么

Data Matrix ECC200，**方形**符号，文本载荷，字段集合与[贴片编码协议 V1](../../../简报/附件/2026-10-06-贴片编码协议.md) 的 01–07 **一一对应**，只是编码方式从 TLV 二进制换成了文本：

```text
CGPATCH/1|patchId=<UUID>|model=1|lot=DEMO-2607xx|mfg=2026-07-01|exp=2027-07-01|maxUseMin=120|calRef=DEMO-CAL
```

**为什么是文本不是 V1 二进制**：签名工具与密钥都还没有，二进制包端到端验不了。字段名与 V1 一致，将来切二进制只改编解码一处，数据库列与界面不动。

## 规格

- 40×40（A）与 44×44（B、C）；D/E/F 载荷短，符号也小
- 强制方形（`SymbolShapeHint.FORCE_SQUARE`）：不加的话短载荷会被编成 8×18 这类长方形，跟贴片规格对不上
- 四周 2 个模块白边（Data Matrix 最小白边是 1 个模块，贴片印刷规格按 2X 留）
- 投屏图每模块 16 像素，打印页每模块 12 像素

对照贴片印刷的 16×16 mm 码区：44 个模块（含白边）落在 16 mm 内是 0.36 mm/模块，600 dpi 下约 8.6 个打印点，比协议里写的「每模块 6 点」还宽松，尺寸够。

## 重新生成

需要 `zxing-core`（只用到 core，不用 javase）：

```bash
curl -o /tmp/zxing-core.jar \
  https://maven.aliyun.com/repository/public/com/google/zxing/core/3.5.3/core-3.5.3.jar
cd docs/SOP/架构/附件/贴片样例
javac -encoding UTF-8 -cp /tmp/zxing-core.jar -d /tmp/patchgen Gen.java
java -cp "/tmp/patchgen:/tmp/zxing-core.jar" Gen .     # Windows 上分隔符用 ;
```

`Gen` 写完会**自己回读验证**：把刚写出的 PNG 重新解码，跟载荷逐字节比对，对不上直接抛异常。打印页按块裁开逐枚解——整页多码识别（`GenericMultipleBarcodeReader`）在一张图上找六个，检测器挑错区域就全军覆没，而人扫打印页本来也是一枚一枚对准的。

`java Gen.java` 那种单文件源码启动在 Windows 上会在最后一步炸在 jdk.compiler 里（`IllegalArgumentException`），所以先 `javac` 再 `java`。

2026-10-16 生成时回读结果：**六枚单张 + 打印页六枚，载荷全部逐字节一致**。

## 已知边界

- 这是屏幕上/打印纸上的码。**贴片实物的可读性**（曲面、哑光面材、汗液、光照）属于标签工艺验收，不在这里覆盖。
- 载荷未签名，App 本期也不验签。等密钥与签发工具就位后，这里要换成 V1 二进制包并补一组签名样本。
- 六枚同屏时每枚码在 1080p 屏上约 8 px/模块，比单枚视图小得多。**离得远或手抖时解不出来是正常的**，别把它当成"多码点选坏了"——先切回单枚视图确认单码链路是通的。
