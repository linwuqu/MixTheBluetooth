## 0. 一句话

**生产侧是 effect flow 内的解析管道(字节流 → 记录流),消费侧是状态机 reduce 内的校验链(累积 → 触发 → 结论);读流程与短命令(对时/删除)是两条独立状态机,互不干扰;两者之间只流通一种东西:`RecordsProduced` 事件。**

```text
字节流(蓝牙 DataReceived)
  → [flow 内] SessionTextDecoder → LineAssembler → RecordParser   ← 生产,有状态,随会话生灭
  → RecordsProduced 事件(经 orchestrator 队列)
  → [reduce 内] 累积 → END marker 触发校验链 → 结论(WriteFile+SendDelete / RetryRead)  ← 消费,纯函数
```

## 1. 设计疑点与评审结论

### 1.1 生产侧:解析管道是 effect flow,不是状态机的状态

疑点:"运行时是什么?为什么状态机没有对应状态?三个类为什么不组成上下游流?"

答案:现有基础设施里,effect 返回 `Flow<Event>`,由 `WorkflowOrchestrator` 在独立作用域执行、把产出事件送回事件队列:

```kotlin
// WorkflowOrchestrator(已施工):effect 的执行就是 flow 的收集
transition.effects.forEach { effect ->
    effectScope.launch { effectExecutor(effect).collect(events::send) }
}
```

所以**命令会话 = 一条 effect flow**。`StartRead(session)` 的 flow 体内:

1. 编码指令 → 蓝牙 `SendData`
2. 收集蓝牙事件流:`DataReceived` 字节块逐块喂给解析管道;`DataSent` 累计到发送字节数 → 发 `CommandAccepted`;`Disconnected` → 发 `DeviceDisconnected`
3. 管道产出的完整记录 → 发 `RecordsProduced` 事件

三个解析器就是管道上三个有状态环节,每次调用顺序执行,状态(尾巴)在对象内部。**管道生命周期 = flow 生命周期 = 会话生命周期**——flow 结束(命令完成/超时/取消),解析器随之销毁,尾巴自然消失,无需额外"运行时"对象。

状态机只管会话阶段,不管解析——这就是为什么状态机里没有"解析状态"。

### 1.2 消费侧:校验链在 reduce 内,触发点是 END marker

疑点:"从生产到消费的函数怎么排列?逻辑断线。"

答案:连接点是 `RecordsProduced` 事件,触发点是 **END marker 出现在本批记录里**:

```text
Receiving(session, accumulated) + RecordsProduced(records)
  → accumulated + records 追加
  → 本批有 Marker(END) 吗?
       ├─ 无 → Transition(Receiving(新累积), 无 effect)   ← 继续等,不发任何 effect
       └─ 有 → validate(全量):边界规整 → marker → 去重 → 结构(纯函数,reduce 内直接调)
              ├─ 完整 → Completed + [WriteFile, SendDelete]
              └─ 不完整 → Failed(retryCount+1) + [RetryRead 或 StopRuntime(RETRY_EXHAUSTED)]
```

校验是纯函数(见 §7),记录全部在 State 里,所以可以安全地放在 reduce 里执行——这就是"消费侧"。生产只管"解析出记录",消费只管"累积到 END 后下结论"。

### 1.3 读与短命令拆分离线(评审第 4 点)

疑点:"对时 ack 怎么会直接停止(StopRuntime)?写在一起容易乱。"

结论:**拆成两条独立状态机**,同一 Translation 内两个 orchestrator,互斥由 Translation 控制:

| | 读状态机 `CgmReadDecision` | 短命令状态机 `CgmShortDecision` |
|---|---|---|
| 状态 | Idle → Sending → Receiving → Completed(双闸门)→ Stopped / Failed(重读)→ Stopped | Idle → Sending → WaitingAck → **Done**(对时成功/删除成功)/ Failed |
| 终点语义 | 文件落盘 + 删除确认都到 → 会话结束 | **Done 就是终态**,没有"停止"概念 |
| 删除确认 | `AckReceived(DELETE)` 只作为 Completed 的闸门 | 无(短命令自己就是删除) |
| 超时 | 重读(累积保留),上限 3 次 | 直接 Failed,不重试 |

两个 orchestrator 各自 `effectExecutor = port::execute`,事件回各自的队列,互不相通。同一 CgmPortAdapter 实例。**串行互斥与切换保护是三层防护**(UI 禁用 → Translation 隐式切换 → 状态机兜底),见 1.7。

### 1.4 单一事件通道与信道纯净度(评审第 2、3 点)

疑点:"sendData 不光要监听 received,output 的 ack 和 mtu 要不要监听?怎么区分?怎么保证信道纯净度?"

结论:**所有设备事件走同一个通道**(`ConnectionSession.output`),事件类型即身份,不靠顺序猜。纯净度由**串行会话的唯一消费者**保证:

```text
连接生命周期内,output 通道的消费者至多一个:
  连接中  → Connect flow 收集(只认 Connected/ConnectFailed/ConnectTimeout,其他丢弃)
  命令中  → SendData flow 收集(只认 DataReceived/DataSent/MtuChanged/Disconnected)
同一时刻不可能有两个消费者(连接完成后才发命令;命令完成后才断开)——这就是纯净度。
```

早期版本的"received 通道 + output 通道"双通道设计是错的:连接成功后 Connect flow 结束,output 无人收集,`DataSent`/`MtuChanged`/`Disconnected` 全被丢弃。统一通道后,`sendData` flow 一个 collect 处理全部设备事件,分派干净。

**RequestMtu 考察结论(评审第 3 点)**:旧库 `AllBluetoothManage.setMTU(module, mtu)`(23~512)存在,但默认 `mModuleMtu = 20` 且收到更大包自动放大(自适应);`BluetoothLeService` 只在"文件发送"场景才主动拉 512。我们的发送只有三条小指令(≤30B),MTU 不影响;接收是设备主动推,库自适应。结论:**保留 `RequestMtu` 能力(一行桥接,可选),默认不干预;`MtuChanged` 事件保留用于诊断日志**。

### 1.5 完整数据链路(评审第 5 点)

从旧库回调到状态机的完整链路,每一跳的形态与归属:

```text
旧库 readData(mac, bytes) 块交付(缓冲满/300ms 静默)
  → HcBluetoothLibraryClient.onDataReceived(bytes)      [IBluetooth 桥接]
  → AndroidBluetoothPort.onDataReceived → session.output.trySend(DataReceived)   [通道]
  → SendData flow 的 collect 转发(launch { receiveAsFlow().collect { trySend(it) } })   [通道消费者]
  → CgmPortAdapter.readFlow 的 collect 收到 BluetoothEvent.DataReceived
  → pipeline.parse(event.data)                          [SequentialCgmParsePipeline:解码→切行→解析]
  → 非空 → emit(CgmReadEvent.RecordsProduced(sessionId, records))
  → WorkflowOrchestrator events 队列
  → reduce.onRecords:累积 + END 触发校验链
```

`pipeline.parse(event.data)` 的输入就是 `sendData` flow 转发上来的 `DataReceived` 载荷——正是用户确认的连接点。

### 1.6 RetryRead / StopRuntime 的真实语义

`RetryRead` / `StopRuntime` 是普通 effect,由 CgmPortAdapter 执行:

- `RetryRead(session, reason)`:复用读命令 flow(重发 ALL)。发送确认后 reduce 从 `Failed` 回到 `Receiving`,**已累积记录保留**继续累积
- `StopRuntime(session, reason)`:会话结束信号。**当前 WorkflowOrchestrator 的 effect 是独立协程,没有外部强制取消机制**——所以"停止"是协作式的:状态进入 Stopped/Failed/Completed 后,迟到的同会话事件在 reduce 里被忽略(幂等),在途 flow 自然结束。StopRuntime 是显式信号 effect(adapter 里空 flow),方便测试与日志;短命令状态机不需要它(Done/Failed 即终态)

### 1.7 时分复用的三层防护(评审第 1 点)

疑点:"单通道时分复用,用户乱按怎么办?先对时再读、读一半删、指令途中变更——UI 要防护,状态机也要防护,确保程序不失序。"

结论:通道只有一个,命令同一时刻只能有一条在飞。保证"不会失序"靠**三层防护**,每一层都是独立机制,任何一层被绕过都有下一层兜底:

| 层 | 机制 | 防什么 |
|---|---|---|
| **① UI 层** | 按钮常亮可点(不做视觉禁用);冲突点击由 ② 给出 toast 反馈,不静默 | 用户点错有明确反馈,不会误以为命令已发出 |
| **② 翻译层** | `submit` 是通往 orchestrator 的**唯一入口**:冲突(任一侧活跃)→ **拒绝执行 + report Blocked(toast 提示等待)**;Error 态自动复位后再执行 | 保证不会产生两个并发命令 effect;昂贵操作(读)不被静默打断 |
| **③ 状态机层** | 活跃状态收到新命令/迟到事件 → 忽略(幂等);`StopCurrent` 任意状态 → Stopped;`Error` + `ResetError` → Idle | 兜底:即使事件乱序到达,reduce 也不会产生非法转移 |

三层的关系:**UI 防"静默无反馈",Translation 防"发不出去",状态机防"算不出来"**。

**互转策略(评审第 3 点修订)**:**任何状态互转的冲突都不隐式执行,而是 toast 提示"正在读取缓存中 / 正在对时中,请等待执行完毕"并拒绝**——因为读是昂贵操作(分钟级),静默打断会让用户丢失上下文。用户透明的是"状态切换"这件事本身(没有停止/复位按钮、错误自动复位),不是昂贵的读取过程。冲突时的 toast 文案按当前活跃方给出(见 10.2 `CgmOutput.Blocked`)。

**指令途中变更的真正风险在蓝牙层**:若未来放行切换,旧读 flow 还没结束(无强制取消),新旧两个 SendData flow 会同时收集同一个 output 通道——通道时分复用被打破。**这一层仍由通道消费权转移解决**(见 3.3):新命令 flow 启动时夺走通道收集权,旧 flow 收不到事件自然失效。当前互转策略下不触发,但保留作为防御性机制(防绕过 Translation 直连)。

**停止/复位的用户语义(评审第 3 点)**:用户不会显性点"停止"再点别的,也不会主动"重置错误"——所以 UI 不暴露 Stop 与 ResetError 按钮,这两个意图降为**内部机制**:点任何命令时若处于 Error,内部先 `ResetError` 再开始(复位无感,不 toast);活跃冲突则不切换、toast 等待提示。错误不以占屏状态展示,至多 toast(见 10.1、11.5)。

## 3. 文件 01-03:蓝牙 Port 能力扩展(改)

### 3.1 BluetoothPort.kt — 能力契约扩展

```kotlin
sealed interface BluetoothEffect {
    data class Connect(val deviceId: String, val timeoutMillis: Long = 15_000) : BluetoothEffect
    data object Disconnect : BluetoothEffect
    data class SendData(val data: ByteArray) : BluetoothEffect      // 发指令(旧库内部分包+节流)
    data class RequestMtu(val mtu: Int) : BluetoothEffect           // 可选:默认不调用(见 1.4 考察结论)
}

sealed interface BluetoothEvent {
    data class Connected(val device: BluetoothDeviceInfo) : BluetoothEvent
    data class ConnectFailed(val message: String) : BluetoothEvent
    data object ConnectTimeout : BluetoothEvent
    data object Disconnected : BluetoothEvent
    data class DataReceived(val data: ByteArray) : BluetoothEvent   // 收:块交付,边界任意
    data class DataSent(val bytesSent: Int) : BluetoothEvent        // readNumber 每包 ACK
    data class MtuChanged(val mtu: Int) : BluetoothEvent            // 诊断用
}
```

要点:

- `DataReceived` 是**事件流(channel 语义,消费即消失)**:连接期间旧库持续回调,有没有人收集由上层决定。上层会话(命令 flow)结束后的数据 trySend 失败即丢弃——这就是"会话外的游离数据"在能力层的自然表现
- **`readNumber` 回调没有设备参数**(SDK 签名限制)→ DataSent 只能路由给"当前连接会话"。串行会话(同一时刻只有一个命令在飞)天然满足,这是硬约束
- 命名:`bytesSent` 明确表达"本包发送字节数",与 SDK `readNumber(number)` 区分(桥接层改名)

### 3.2 HcBluetoothLibraryClient.kt — 桥接回调与发送

```kotlin
internal interface BluetoothLibraryListener {
    fun onConnected(device: BluetoothDeviceInfo)
    fun onConnectionLost(deviceId: String?)
    fun onDataReceived(data: ByteArray)            // readData 桥接
    fun onDataSent(bytesSent: Int)                 // readNumber 桥接
    fun onMtuChanged(mtu: Int)                     // callbackMTU 桥接
}
```

```kotlin
    @Volatile var connected: Boolean = false,
    var dataCollector: Job? = null

}

override fun onMtuChanged(mtu: Int) {

    session?.output?.trySend(BluetoothEvent.MtuChanged(mtu))

    is BluetoothEffect.Connect -> connect(effect.deviceId, effect.timeoutMillis)
    BluetoothEffect.Disconnect -> disconnect()
    is BluetoothEffect.SendData -> sendData(effect.data)
    is BluetoothEffect.RequestMtu -> requestMtu(effect.mtu)
}

private fun sendData(data: ByteArray): Flow<BluetoothEvent> = callbackFlow {
    val session = synchronized(lock) {
        connectionSession?.takeIf { it.connected }
    } ?: run {
        trySend(BluetoothEvent.ConnectFailed("未连接,无法发送")); close(); return@callbackFlow
    }
    val sent = runCatching { client.sendData(session.deviceId, data) }
    if (sent.isFailure || !sent.getOrDefault(false)) {
        trySend(BluetoothEvent.ConnectFailed("发送失败")); close(); return@callbackFlow
    }
    // 消费权转移(时分复用的关键):新命令夺走通道收集权,旧命令收集器被 cancel 后
    // 收不到事件自然失效(awaitClose 触发,旧 flow 结束)——"指令途中变更"不会造成
    // 双消费者并发,通道时分复用得以维持(1.7 第三道防护在蓝牙层的实现)
    synchronized(lock) {
        session.dataCollector?.cancel()
    }
    // 唯一消费者:转发该会话通道的全部设备事件(类型即身份,不靠顺序猜)
    val collector = launch {
        synchronized(lock) { session.dataCollector = coroutineContext[Job] }
        session.output.receiveAsFlow().collect { event ->
        session.output.receiveAsFlow().collect { event ->
            when (event) {
                is BluetoothEvent.DataReceived,
                is BluetoothEvent.DataSent,
                is BluetoothEvent.MtuChanged,
                is BluetoothEvent.Disconnected -> trySend(event)
                // 连接期事件在发送期不会出现(连接成功后才有发送),丢弃是安全兜底
                is BluetoothEvent.Connected,
                is BluetoothEvent.ConnectFailed,
                BluetoothEvent.ConnectTimeout -> Unit
            }
        }
    }
    awaitClose { collector.cancel() }
}
```

要点:

- **通道容量**:`output` 由 Connect flow 以 `Channel.BUFFERED` 创建(现有代码,容量 64 事件)。发送会话期间收集者常驻,不会积压;会话结束后无人收集,事件缓冲——满 64 后 `trySend` 失败即丢弃,这是**设计意图**(会话外数据本来就不要),回调线程永不阻塞(`trySend` 非挂起)
- **纯净度**:连接生命周期内消费者至多一个(连接中=Connect flow,命令中=SendData flow,串行互斥);事件类型区分,不依赖到达顺序
- **Connect flow 无需改动**:它只认连接事件,连接期不会有数据事件,不会误丢
- `requestMtu` 与 sendData 同构,默认业务不调用(见 1.4)

```kotlin
package com.biosensor.migratedev.decisioncore.cgm

import com.biosensor.migratedev.decisioncore.DecisionCore
import com.biosensor.migratedev.decisioncore.Transition

// State / Event / Effect 词汇在 CgmContracts.kt(文件 04)

object CgmReadDecision : DecisionCore<CgmReadState, CgmReadEvent, CgmReadEffect> {
    private const val RETRY_LIMIT = 3

    override fun reduce(
        currentState: CgmReadState, event: CgmReadEvent
    ): Transition<CgmReadState, CgmReadEffect> = when (event) {
        is CgmReadEvent.ReadRequested -> onRequested(currentState, event)
        is CgmReadEvent.CommandAccepted -> onAccepted(currentState, event)
        is CgmReadEvent.AckReceived -> onDeleteAck(currentState, event)
        is CgmReadEvent.RecordsProduced -> onRecords(currentState, event)
        is CgmReadEvent.FileWritten -> onFileWritten(currentState, event)
        is CgmReadEvent.FileWriteFailed -> Transition(CgmReadState.Error(event.message))
        is CgmReadEvent.CommandTimeout -> onTimeout(currentState, event)
        is CgmReadEvent.DeviceDisconnected -> {
            val session = currentState.session ?: return Transition(currentState)
            // 无活跃会话:迟到的断开事件幂等忽略
            Transition(
                CgmReadState.Failed(session, emptyList(), "设备断开", 0),
                listOf(CgmReadEffect.StopRuntime(session, StopReason.DISCONNECTED)))
        }
        is CgmReadEvent.StopCurrent -> {
            val session = currentState.session ?: return Transition(currentState)
            Transition(
                CgmReadState.Stopped(session),
                listOf(CgmReadEffect.StopRuntime(session, StopReason.USER_CANCEL)))
        }
        CgmReadEvent.ResetError -> when (currentState) {
            is CgmReadState.Error -> Transition(CgmReadState.Idle)
            else -> Transition(currentState)
        }
    }

    private fun onRequested(
        current: CgmReadState, event: CgmReadEvent.ReadRequested
    ): Transition<CgmReadState, CgmReadEffect> = when (current) {
        CgmReadState.Idle, is CgmReadState.Completed, is CgmReadState.Failed,
        is CgmReadState.Stopped, is CgmReadState.Error -> {
            val session = CgmSession(event.sessionId, event.deviceId)
            Transition(
                CgmReadState.Sending(session),
                listOf(CgmReadEffect.StartRead(session)))
        }
        else -> Transition(current)   // 串行会话:活跃中忽略(UI 主防)
    }

    private fun onAccepted(
        current: CgmReadState, event: CgmReadEvent.CommandAccepted
    ): Transition<CgmReadState, CgmReadEffect> = when (current) {
        is CgmReadState.Sending -> Transition(
            CgmReadState.Receiving(current.session, emptyList(), retryCount = 0))
        // 重读路径:RetryRead 重发 ALL 后,确认回到 Receiving,保留已累积记录
        is CgmReadState.Failed -> Transition(
            CgmReadState.Receiving(current.session, current.accumulated, current.retryCount))
        else -> Transition(current)
    }

    /** 删除确认:Completed 双闸门之一(filePath 与 deleteAcked 都到才 Stopped)。 */
    private fun onDeleteAck(
        current: CgmReadState, event: CgmReadEvent.AckReceived
    ): Transition<CgmReadState, CgmReadEffect> = when (current) {
        is CgmReadState.Completed -> if (event.purpose == CgmCommandPurpose.DELETE) {
            val done = current.filePath != null
            Transition(
                if (done) CgmReadState.Stopped(current.session) else current.copy(deleteAcked = true),
                if (done) listOf(CgmReadEffect.StopRuntime(current.session, StopReason.COMPLETED))
                else emptyList())
        } else Transition(current)
        else -> Transition(current)
    }

    /** 读取数据:累积 + 校验触发点(消费侧,见 §1.2)。 */
    private fun onRecords(
        current: CgmReadState, event: CgmReadEvent.RecordsProduced
    ): Transition<CgmReadState, CgmReadEffect> {
        if (current !is CgmReadState.Receiving || current.session.id != event.sessionId) {
            return Transition(current)   // 会话已结束/不匹配:迟到的记录忽略(幂等)
        }
        val all = current.accumulated + event.records
        val endReached = event.records.any {
            it is CgmRecord.Marker && it.kind == MarkerKind.END
        }
        if (!endReached) {
            return Transition(current.copy(accumulated = all))   // 继续累积,无 effect
        }
        val conclusion = CacheValidators.validate(all)   // 纯函数
        if (conclusion.complete) {
            return Transition(
                CgmReadState.Completed(current.session, filePath = null, deleteAcked = false),
                listOf(
                    CgmReadEffect.WriteFile(current.session, conclusion.records),
                    CgmReadEffect.SendDelete(current.session)))
        }
        val retry = current.retryCount
        val exhausted = retry + 1 > RETRY_LIMIT
        return Transition(
            CgmReadState.Failed(current.session, all, conclusion.reason ?: "校验未通过", retry + 1),
            listOf(
                if (exhausted) CgmReadEffect.StopRuntime(current.session, StopReason.RETRY_EXHAUSTED)
                else CgmReadEffect.RetryRead(current.session, conclusion.reason ?: "校验未通过")))
    }

    private fun onFileWritten(
        current: CgmReadState, event: CgmReadEvent.FileWritten
    ): Transition<CgmReadState, CgmReadEffect> = when (current) {
        is CgmReadState.Completed -> {
            val done = current.deleteAcked
            Transition(
                if (done) CgmReadState.Stopped(current.session) else current.copy(filePath = event.path),
                if (done) listOf(CgmReadEffect.StopRuntime(current.session, StopReason.COMPLETED))
                else emptyList())
        }
        else -> Transition(current)
    }

    private fun onTimeout(
        current: CgmReadState, event: CgmReadEvent.CommandTimeout
    ): Transition<CgmReadState, CgmReadEffect> = when (current) {
        is CgmReadState.Sending -> Transition(
            CgmReadState.Failed(current.session, emptyList(), "发送超时", 0),
            listOf(CgmReadEffect.StopRuntime(current.session, StopReason.TIMEOUT)))
        // 读取超时:重读(累积保留);到上限则结束
        is CgmReadState.Receiving -> {
            val retry = current.retryCount
            val exhausted = retry + 1 > RETRY_LIMIT
            Transition(
                CgmReadState.Failed(current.session, current.accumulated, "接收超时", retry + 1),
                listOf(
                    if (exhausted) CgmReadEffect.StopRuntime(current.session, StopReason.RETRY_EXHAUSTED)
                    else CgmReadEffect.RetryRead(current.session, "接收超时")))
        }
        else -> Transition(current)
    }

    private val CgmReadState.session: CgmSession?
        get() = when (this) {
            // 逐类型分支 + this. 前缀:避免递归解析到本扩展属性自身
            is CgmReadState.Sending -> this.session
            is CgmReadState.Receiving -> this.session
            is CgmReadState.Completed -> this.session
            is CgmReadState.Failed -> this.session
            is CgmReadState.Stopped -> this.session
            else -> null
        }
}
```

## 7. 文件 07:CacheValidators.kt(新)— 消费侧校验链

```kotlin
package com.biosensor.migratedev.decisioncore.cgm

/** 校验链:边界规整 → marker → 去重 → 结构。全部纯函数,由 CgmReadDecision.onRecords 在 END 到达时调用。 */
object CacheValidators {
    fun validate(records: List<CgmRecord>): ValidationConclusion {
        // ① 边界规整:真实设备在首个 Start Playback 前可能残留杂散行(实测样本首行 EIS:2,70),
        //    只取首个 START 到末个 END 之间的记录,保证后续校验看的就是一次完整回放
        val bounded = CacheBoundaryTrimmer.trim(records)
        if (bounded.isEmpty()) return ValidationConclusion(false, "缺少 Start Playback / Playback all done 边界")
        // ② marker 校验:必须在去重之前(去重会删 marker,见下)
        val marker = CacheMarkerValidator.validate(bounded)
        if (!marker.ok) return ValidationConclusion(false, marker.message)
        // ③ 去重:数据行内容全等(原始行文本)保序保留首条;marker 全部剔除(边界已由 render 补齐)
        val deduped = CacheRecordDeduper.dedupe(bounded)
        // ④ 结构校验:按 LOG 段声明骨架逐段验证(实测:每段 seq 从 1 连续、点数与声明一致)
        val structure = CacheStructureValidator.validate(deduped)
        if (!structure.ok) return ValidationConclusion(false, structure.message)
        return ValidationConclusion(true, null, deduped)
    }
}

data class ValidationConclusion(
    val complete: Boolean, val reason: String? = null, val records: List<CgmRecord> = emptyList()
)

/** 边界规整:首个 START 到末个 END 之间的记录(兜底 reduce 未过滤的杂散行,见 §1.2 修订注)。 */
object CacheBoundaryTrimmer {
    fun trim(records: List<CgmRecord>): List<CgmRecord> {
        val startIdx = records.indexOfFirst {
            it is CgmRecord.Marker && it.kind == MarkerKind.START
        }
        val endIdx = records.indexOfLast {
            it is CgmRecord.Marker && it.kind == MarkerKind.END
        }
        if (startIdx < 0 || endIdx < 0 || startIdx > endIdx) return emptyList()
        return records.subList(startIdx, endIdx + 1)
    }
}

/**
 * 去重:只删**相邻**重复行(蓝牙字节块重发会在相邻位置产生相同记录),保序保留首条;
 * 跨段相同文本(实测:不同快照中某点的值可能恰巧相同,如 EIS:18 同时出现在两个段)是合法数据,不能删;
 * marker 剔除(边界由 render 补齐,不参与去重判据)。
 */
object CacheRecordDeduper {
    fun dedupe(records: List<CgmRecord>): List<CgmRecord> {
        val data = records.filter { it !is CgmRecord.Marker }
        if (data.isEmpty()) return data
        val result = mutableListOf(data.first())
        for (record in data.drop(1)) {
            if (record.text != result.last().text) result += record
        }
        return result
    }
}

/** marker 校验:边界成对(首 START / 尾 END)。对规整后的序列做,此时首尾必然各有一个。 */
object CacheMarkerValidator {
    data class MarkerResult(val ok: Boolean, val message: String? = null)

    fun validate(records: List<CgmRecord>): MarkerResult {
        val first = records.firstOrNull()
        val last = records.lastOrNull()
        return if (first is CgmRecord.Marker && first.kind == MarkerKind.START &&
            last is CgmRecord.Marker && last.kind == MarkerKind.END
        ) {
            MarkerResult(ok = true)
        } else {
            MarkerResult(false, "marker 边界异常(缺 Start Playback / Playback all done)")
        }
    }
}

/**
 * 结构校验:以 LOG 段声明为骨架——`LOG:段号,类型,点数,时间`,类型 1=EIS 段(seq 1..95 连续、ts 60 步进 10)、
 * 2=CA 段(seq 1..N 连续,N 由声明给出,实测 213/266/268)。每段实际记录数必须与声明点数一致;
 * summarize 是段间隔记录,跳过。与实测三样本(07-15/07-20/07-21)严格对应。
 */
object CacheStructureValidator {
    data class StructureResult(val ok: Boolean, val message: String? = null)

    /** 解析 `LOG:段号,类型,点数,时间` → (type, count);格式异常返回 null。 */
    private fun parseLog(text: String): Pair<Int, Int>? {
        val m = LOG_SEGMENT_PATTERN.find(text) ?: return null
        return m.groupValues[1].toInt() to m.groupValues[2].toInt()
    }

    fun validate(records: List<CgmRecord>): StructureResult {
        var expect: SegmentExpect? = null
        for (record in records) {
            when (record) {
                is CgmRecord.Log -> {
                    // 上一段结算:新声明到来时,若上一段未收满声明点数则失败
                    expect?.let {
                        if (it.seen != it.count) {
                            return StructureResult(false, "段 ${it.type} 声明 ${it.count} 点,实际 ${it.seen} 点")
                        }
                    }
                    val decl = parseLog(record.text) ?: return StructureResult(false, "LOG 段声明格式异常: ${record.text}")
                    val (type, count) = decl
                    if (type !in EIS_TYPE..CA_TYPE) return StructureResult(false, "未知段类型: $type")
                    expect = SegmentExpect(type, count)
                }
                is CgmRecord.Summarize -> Unit   // 段间隔记录,跳过
                is CgmRecord.Marker -> Unit      // 去重已剔除,防御性跳过
                else -> {
                    val cur = expect ?: return StructureResult(false, "数据行前无段声明: ${record.text}")
                    when (cur.type) {
                        EIS_TYPE -> {
                            val eis = record as? CgmRecord.Eis
                                ?: return StructureResult(false, "EIS 段第 ${cur.seen + 1} 条非 EIS: ${record.text}")
                            if (eis.seq != cur.seen + 1) {
                                return StructureResult(false, "EIS seq ${eis.seq} 应为 ${cur.seen + 1}(连续)")
                            }
                            val expectedTs = 60 + cur.seen * 10
                            if (eis.ts != expectedTs) {
                                return StructureResult(false, "EIS ts ${eis.ts} 应为 $expectedTs(60 起步步进 10)")
                            }
                        }
                        CA_TYPE -> {
                            val ca = record as? CgmRecord.Ca
                                ?: return StructureResult(false, "CA 段第 ${cur.seen + 1} 条非 CA: ${record.text}")
                            if (ca.seq != cur.seen + 1) {
                                return StructureResult(false, "CA seq ${ca.seq} 应为 ${cur.seen + 1}(连续)")
                            }
                        }
                    }
                    cur.seen += 1
                }
            }
        }
        // 尾部结算:数据结束,最后一段未收满声明点数 → 不完整
        expect?.let {
            if (it.seen != it.count) {
                return StructureResult(false, "段 ${it.type} 声明 ${it.count} 点,实际 ${it.seen} 点")
            }
        }
        // 只有段声明没有数据点(全为 LOG/summarize)→ 不完整
        if (records.none { it is CgmRecord.Eis || it is CgmRecord.Ca }) {
            return StructureResult(false, "没有数据点")
        }
        return StructureResult(ok = true)
    }

    private data class SegmentExpect(val type: Int, val count: Int, var seen: Int = 0)

    private const val EIS_TYPE = 1
    private const val CA_TYPE = 2
    private val LOG_SEGMENT_PATTERN = Regex("""LOG:\d+,(\d+),(\d+),""")
}
```

要点:

- **校验顺序为什么是 规整 → marker → 去重 → 结构**:实测样本在首个 START 前有杂散行(`EIS:2,70`),先规整才能保证 marker 首尾成对;marker 校验必须在去重前(去重会剔除 marker,否则"删了再查首尾"必然失败);结构校验只在去重后的数据上做
- **规整取"首 START..首 END"而非"首 START..末 END"**:语义与状态机对齐(§5 onRecords)——首个 END 到达即触发校验,此时 accumulated 只含第一份完整推送;之后的重复推送与推间杂散(实测 07-21 每份推送之间有散落 EIS 行)在 Completed 后被幂等忽略,不参与校验
- **去重只删"相邻"重复行,不能全局 distinctBy**:字节块重发会在相邻位置产生相同记录,删相邻即够;实测不同快照段的同名点值可能恰巧相同(EIS:18 同时出现在 LOG:1 与 LOG:3 段),全局去重会把后者的合法记录误删、破坏段内连续性
- **为什么校验时全量去重而不是累积时去重**:去重判据跨批次(整段重发可能分散在不同 RecordsProduced),累积原样追加(内存 ~百 KB,无压力),END 到达后一次去重——纯函数,单测友好
- **结构校验是"段声明骨架"而非"固定轮"**:实测三个样本的段类型/点数均不同(07-15: EIS95+CA266×2+EIS95+CA213;07-20: 10 段含 CA268;07-21: 3 段含 CA268),唯一不变规律是 *LOG 声明点数 == 段内实际点数*、*段内 seq 从 1 严格连续*、*EIS 段 ts 60 起步步进 10*——校验规则从声明出发,点数/类型可变的设备行为全部覆盖
- **重复推送是设备常态**:同一缓存(Start..Playback all done)被原样推送 3-5 次,但首个 END 触发校验意味着只看首份,重复推送根本进不了校验输入(Completed 幂等忽略);07-20 的 10 段里新旧数据并存(旧 LOG:1..4 + 当天新 LOG:5..10),均在首份内一次收齐

## 8. 文件 08:CgmParsePipeline.kt(新)— 生产侧解析管道

```kotlin
package com.biosensor.migratedev.orchestrator.cgm

import com.biosensor.migratedev.decisioncore.cgm.CgmRecord
import com.biosensor.migratedev.decisioncore.cgm.MarkerKind
import java.nio.ByteBuffer
import java.nio.CharBuffer
import java.nio.charset.CharacterCodingException
import java.nio.charset.Charset
import java.nio.charset.CharsetDecoder
import java.nio.charset.CodingErrorAction

/** 管道接口:每次输入一个字节块,输出该块产出的完整记录。状态(尾巴)在实现内。 */
fun interface CgmParsePipeline {
    suspend fun parse(bytes: ByteArray): List<CgmRecord>
}

/** 顺序管道:解码 → 切行 → 记录解析,一次调用即流水线一步。 */
class SequentialCgmParsePipeline : CgmParsePipeline {
    private val decoder = SessionTextDecoder()
    private val assembler = LineAssembler()
    private val parser = RecordParser()

    override suspend fun parse(bytes: ByteArray): List<CgmRecord> {
        val text = when (val out = decoder.accept(bytes)) {
            is SessionTextDecoder.Output.Text -> out.text
            is SessionTextDecoder.Output.Failed -> return emptyList()   // 本块解码失败:丢弃,等待下块
        }
        return assembler.accept(text).mapNotNull(parser::parse)
    }
}

/** ① 字节 → 文本:管"多字节字符被块切开"的尾巴。 */
class SessionTextDecoder(
    private val charsetName: String = "GBK"   // 沿用旧 app 默认编码,会话内固定
) {
    private val decoder: CharsetDecoder = Charset.forName(charsetName).newDecoder()
        .onMalformedInput(CodingErrorAction.REPORT)       // 非法序列直接报错,不静默替换
        .onUnmappableCharacter(CodingErrorAction.REPORT)

    private var pendingBytes: ByteArray = byteArrayOf()   // 尾巴:解码器没消费完的字节

    sealed interface Output {
        data class Text(val text: String) : Output
        data class Failed(val message: String) : Output
    }

    fun accept(bytes: ByteArray): Output {
        val input = ByteBuffer.wrap(pendingBytes + bytes)
        val output = CharBuffer.allocate((pendingBytes.size + bytes.size) * 2)
        return try {
            decoder.decode(input, output, endOfInput = false)   // 增量式:可能留尾巴
            pendingBytes = input.slice().toByteArray()          // 未消费字节 = 被切开的字符尾巴
            output.flip()
            Output.Text(output.toString().replace("\u0000", ""))
        } catch (e: CharacterCodingException) {
            Output.Failed("解码失败($charsetName): ${e.javaClass.simpleName}")
        }
    }
}

/** ② 文本 → 行:管"行被块切开"的尾巴。 */
class LineAssembler {
    private var pendingText: String = ""     // 尾巴:没等来 \n 的半行

    fun accept(text: String): List<String> {
        val joined = pendingText + text
        if (joined.isEmpty()) return emptyList()
        val parts = joined.split('\n')
        if (parts.size == 1) {               // 整段都是半行
            pendingText = joined
            return emptyList()
        }
        val complete = parts.dropLast(1)
            .map { it.trimEnd('\r') }        // 清 \r(设备行尾可能是 \r\n)
            .filter { it.isNotEmpty() }      // 块边界产生的空行丢弃
        pendingText = parts.last()
        return complete
    }
}

/** ③ 行 → 结构化记录:保留序号/时间索引元数据;未知行(如 RI)丢弃。 */
class RecordParser {
    fun parse(line: String): CgmRecord? = when {
        line == "Start Playback" -> CgmRecord.Marker(MarkerKind.START, line)
        line == "Playback all done" -> CgmRecord.Marker(MarkerKind.END, line)

        else -> {
            val eis = EIS_PATTERN.matchEntire(line)
            if (eis != null) {
                CgmRecord.Eis(
                    seq = eis.groupValues[1].toInt(),
                    ts = eis.groupValues[2].toInt(),
                    v1 = eis.groupValues[3], v2 = eis.groupValues[4],
                    v3 = eis.groupValues[5], v4 = eis.groupValues[6],
                    text = line
                )
            } else {
                val ca = CA_PATTERN.matchEntire(line)
                if (ca != null) {
                    CgmRecord.Ca(seq = ca.groupValues[1].toInt(), value = ca.groupValues[2], text = line)
                } else when {
                    line.startsWith("LOG:") -> CgmRecord.Log(line)
                    line.startsWith("summarize:") -> CgmRecord.Summarize(line)
                    else -> null            // 未知行(RI 等)→ 丢弃,不产生记录
                }
            }
        }
    }

    companion object {
        val EIS_PATTERN = Regex("""EIS:(\d+),(\d+),([^,]+),([^,]+),([^,]+),([^,]+)""")
        val CA_PATTERN = Regex("""CA:(\d+),([^,]+)""")
    }
}
```

> EIS 的 v1~v4 字段语义待需求方确认(可能为阻抗分量),命名占位,不影响结构。
> 文件边界双保险:解析层丢未知行(RI)→ 累积规则在 reduce 侧再兜一层(END 后事件因状态已非 Receiving 被幂等忽略)。

**管道为什么是 `fun interface` + 顺序调用,而不是 Flow 算子组合**:effect flow 是单收集者(命令 flow 内一个循环),字节块按事件流到达,每次 `parse()` 就是流水线一步——比 `flow { }.transform { }` 链更直接,且状态封装在对象内(每个解析器单测友好)。若未来需要多会话并行,把管道实例放进会话 map 即可。

**管道实例归属**:`CgmPortAdapter` 持有(文件 10)。它的生命周期 = 命令 flow 的生命周期——flow 结束即销毁,与 orchestrator 的 effect 执行模型天然对齐。**不在状态机里,状态机不持有任何有状态 IO 对象**。

### 9.2 CgmPortAdapter.kt

```kotlin
package com.biosensor.migratedev.port.cgm

import com.biosensor.migratedev.decisioncore.cgm.CgmCommandPurpose
import com.biosensor.migratedev.decisioncore.cgm.CgmReadEffect
import com.biosensor.migratedev.decisioncore.cgm.CgmReadEvent
import com.biosensor.migratedev.decisioncore.cgm.CgmRecord
import com.biosensor.migratedev.decisioncore.cgm.CgmSession
import com.biosensor.migratedev.decisioncore.cgm.CgmShortEffect
import com.biosensor.migratedev.decisioncore.cgm.CgmShortEvent
import com.biosensor.migratedev.orchestrator.cgm.CgmParsePipeline
import com.biosensor.migratedev.orchestrator.cgm.SequentialCgmParsePipeline
import com.biosensor.migratedev.port.adapter.bluetoothport.BluetoothEffect
import com.biosensor.migratedev.port.adapter.bluetoothport.BluetoothEvent
import com.biosensor.migratedev.port.adapter.bluetoothport.BluetoothPort
import com.biosensor.migratedev.port.adapter.localport.FileSpace
import com.biosensor.migratedev.port.adapter.localport.LocalFileClient
import java.time.Clock
import java.time.LocalDateTime
import java.time.format.DateTimeFormatter
import kotlinx.coroutines.Dispatchers
import kotlinx.coroutines.flow.Flow
import kotlinx.coroutines.flow.flow
import kotlinx.coroutines.flow.flowOf
import kotlinx.coroutines.flow.flowOn
import kotlinx.coroutines.withTimeoutOrNull
import timber.log.Timber

/**
 * 业务适配器:cqm 业务协议的全部内容。
 * 下行:effect → 蓝牙指令 / 文件落盘;上行:蓝牙事件/落盘结果 → 领域事件。
 * 解析管道在适配器内持有,生命周期 = 命令 flow 生命周期。
 */
class CgmPortAdapter(
    private val bluetooth: BluetoothPort,
    private val fileClient: LocalFileClient,
    private val pipeline: CgmParsePipeline = SequentialCgmParsePipeline(),
    private val clock: Clock = Clock.systemDefaultZone(),
) : CgmPort {

    // ── 读契约 ──
    override fun execute(effect: CgmReadEffect): Flow<CgmReadEvent> = when (effect) {
        // 发起读 / 重读:同一条命令流(重读 = 再发 ALL,累积由状态机保留)
        is CgmReadEffect.StartRead, is CgmReadEffect.RetryRead -> readFlow(effect.session)
        is CgmReadEffect.WriteFile -> writeFileFlow(effect.session, effect.records)
        is CgmReadEffect.SendDelete -> deleteFlow(effect.session)
        is CgmReadEffect.StopRuntime -> flowOf()   // 会话结束信号(协作式停止,见 1.6)
    }

    // ── 短命令契约 ──
    override fun execute(effect: CgmShortEffect): Flow<CgmShortEvent> = when (effect) {
        is CgmShortEffect.SendCommand -> shortFlow(effect.session, effect.purpose)
    }

    // ── 读命令流:发 ALL → 收集 → 解析 → 上报 ──
    private fun readFlow(session: CgmSession): Flow<CgmReadEvent> = flow {
        val payload = "ALL\n\r".encodeToByteArray()
        var sentBytes = 0
        var accepted = false
        val completed = withTimeoutOrNull(COMMAND_TIMEOUT_MILLIS) {
            bluetooth.execute(BluetoothEffect.SendData(payload)).collect { event ->
                when (event) {
                    is BluetoothEvent.DataSent -> {
                        sentBytes += event.bytesSent
                        if (!accepted && sentBytes >= payload.size) {
                            accepted = true
                            emit(CgmReadEvent.CommandAccepted(session.id))   // 命令完整送达
                        }
                    }
                    is BluetoothEvent.DataReceived -> {
                        pipeline.parse(event.data)
                            .takeIf { it.isNotEmpty() }
                            ?.let { emit(CgmReadEvent.RecordsProduced(session.id, it)) }
                    }
                    is BluetoothEvent.Disconnected -> emit(CgmReadEvent.DeviceDisconnected(session.id))
                    else -> Unit   // Connected/MtuChanged 等非会话事件
                }
            }
        }
        if (completed == null) emit(CgmReadEvent.CommandTimeout(session.id))
    }

    // ── 短命令流:发 TIME/DELETE → 等确认 ──
    private fun shortFlow(session: CgmSession, purpose: CgmCommandPurpose): Flow<CgmShortEvent> = flow {
        val payload = encode(purpose).encodeToByteArray()
        var sentBytes = 0
        var accepted = false
        val completed = withTimeoutOrNull(COMMAND_TIMEOUT_MILLIS) {
            bluetooth.execute(BluetoothEffect.SendData(payload)).collect { event ->
                when (event) {
                    is BluetoothEvent.DataSent -> {
                        sentBytes += event.bytesSent
                        if (!accepted && sentBytes >= payload.size) {
                            accepted = true
                            emit(CgmShortEvent.CommandAccepted(session.id))
                        }
                    }
                    is BluetoothEvent.DataReceived -> {
                        // 设备确认文本(形态待实测,TODO);当前以收到数据为确认
                        emit(CgmShortEvent.AckReceived(session.id, purpose))
                    }
                    is BluetoothEvent.Disconnected -> emit(CgmShortEvent.DeviceDisconnected(session.id))
                    else -> Unit
                }
            }
        }
        if (completed == null) emit(CgmShortEvent.CommandTimeout(session.id))
    }

    // ── 读流程的自动删除:确认 = 发送完成(DELETE 后设备不再回放) ──
    private fun deleteFlow(session: CgmSession): Flow<CgmReadEvent> = flow {
        val payload = "DELETE\n\r".encodeToByteArray()
        var sentBytes = 0
        val completed = withTimeoutOrNull(COMMAND_TIMEOUT_MILLIS) {
            bluetooth.execute(BluetoothEffect.SendData(payload)).collect { event ->
                when (event) {
                    is BluetoothEvent.DataSent -> {
                        sentBytes += event.bytesSent
                        if (sentBytes >= payload.size) {
                            emit(CgmReadEvent.AckReceived(session.id, CgmCommandPurpose.DELETE))
                        }
                    }
                    is BluetoothEvent.Disconnected -> emit(CgmReadEvent.DeviceDisconnected(session.id))
                    else -> Unit
                }
            }
        }
        if (completed == null) emit(CgmReadEvent.CommandTimeout(session.id))
    }

    // ── 落盘:文件边界 = Start Playback + 记录行 + Playback all done ──
    private fun writeFileFlow(
        session: CgmSession, records: List<CgmRecord>
    ): Flow<CgmReadEvent> = flow {
        val path = "cgm/${session.id}.txt"
        val ok = runCatching {
            fileClient.sink(FileSpace.RECEIVED, path, append = false).use { sink ->
                sink.write(render(records).encodeToByteArray())
            }
            true
        }.getOrDefault(false)
        Timber.tag(CGM_TAG).i("落盘 session=%s path=%s ok=%s", session.id, path, ok)
        emit(
            if (ok) CgmReadEvent.FileWritten(session.id, path)
            else CgmReadEvent.FileWriteFailed(session.id, "文件写入失败")
        )
    }.flowOn(Dispatchers.IO)

    private fun render(records: List<CgmRecord>): String = buildString {
        appendLine("Start Playback")
        records.forEach { appendLine(it.text) }
        appendLine("Playback all done")
    }

    private fun encode(purpose: CgmCommandPurpose): String = when (purpose) {
        CgmCommandPurpose.SYNC_TIME -> "TIME,${LocalDateTime.now(clock).format(TIME_FORMAT)}\n\r"
        CgmCommandPurpose.READ_ALL -> "ALL\n\r"
        CgmCommandPurpose.DELETE -> "DELETE\n\r"
    }

    private companion object {
        const val CGM_TAG = "Cgm.Port"
        const val COMMAND_TIMEOUT_MILLIS = 60_000L
        val TIME_FORMAT: DateTimeFormatter = DateTimeFormatter.ofPattern("yyyy,MM,dd,HH,mm,ss")
    }
}
```

要点:

- **三条指令 = 三条流**:`readFlow`(ALL,喂解析管道)/ `shortFlow`(TIME|DELETE,等确认)/ `deleteFlow`(读流程自动删,发送完成即确认)——语义各自独立,不再挤在一条流里用 purpose 绕
- **DataSent 是"发送完成"、AckReceived 是"确认"**:发送完成(ΣDataSent ≥ payload)发 `CommandAccepted`;短命令确认当前以"收到设备数据"为准(设备会回文本,形态待实测),若无回复退回"发送完成即确认"(shortFlow 一处判断)
- **超时由适配器发**:`withTimeoutOrNull` 包住整个命令收集,超时发 `CommandTimeout`,reduce 按状态决定重试/结束
- **文件边界在 render()**:落盘内容 = Start Playback + 记录 + Playback all done,与解析侧边界符号严格一致

## 10. 文件 11-13:挂载(Translation + RootWorkflow + RootDecision)

### 10.1 上报机制:Root 与子编排之间想实现什么、为什么、怎么实现(评审第 5 点)

**想实现什么**:Root 是应用级控制流的唯一决策者——它拥有页面展示栈(当前显示哪个业务页面),决定业务间切换(连接完成 → 进入 Cgm 页面;Cgm 读完成 → 后续"生成文件"业务)。子业务(Connection / Cgm / Auth)自己不知道、也不关心"全局接下来去哪",它只负责**本页面内的会话推进**。两者之间因此需要一条**结论通道**:子业务把"会影响整体控制流的结论"上报给 Root,Root 据此转移全局状态、决定页面。

**为什么(为什么不是 Root 直接读子状态)**:子业务的中间状态(正在接收第几轮、累积了多少点)是页面内的过程,Root 不需要、也不该感知——否则 Root 状态会跟着子业务每块数据抖动,全局控制流与页面细节耦合(01 父子编排器架构的核心动机)。所以上报原则是:**只报结论,不报过程**。过程走 `uiState`(页面自己展示),结论走 `report`(Root 决策)。

**怎么实现**:三跳链路——

```text
① 触发点:orchestrator 的 onTransition 钩子(转移发生时同步触发)
   readOrchestrator:双闸门完成(previous 是 Completed 且带 filePath)→ ReadCompleted
                     Failed / Error → Failed
   shortOrchestrator:Done → ShortDone;Failed → Failed
② 通道:Translation 构造时注入 report: (CgmOutput) -> Unit(RootWorkflow 提供)
③ 落点:RootWorkflow 把 CgmOutput 翻译成 RootEvent,dispatch 给 Root orchestrator
   ReadCompleted(path) → RootEvent.CgmCompletedEvent(path)
   Failed(message)     → RootEvent.CgmFailedEvent(message)
   ShortDone(purpose)  → Root 当前不动作(页面内展示,不扰全局)
```

| CgmOutput | 触发时机 | Root 拿它做什么 |
|---|---|---|
| `ReadCompleted(path)` | 双闸门完成(落盘 + 删除确认)→ Stopped | 后续业务入口(生成文件);当前先记录 |
| `Failed(message)` | 读 Failed / 读 Error / 短 Failed | toast 提示;业务上可决定页面回退 |
| `ShortDone(purpose)` | 短命令 Done | 页面内展示为主(对时成功),Root 不动作 |
| `Blocked(hint)` | 互转冲突(任一侧活跃)→ 命令被拒 | toast 提示等待(1.7 ②) |

> 为什么 readOrchestrator 与 shortOrchestrator **都要**挂 onTransition:两者都有"会影响控制流"的终态结论(读完成是业务入口;失败是全局提示)。之前版本只给 short 挂、read 不挂是漏的——读完成恰恰是最重要的上报。

### 10.2 CgmTranslation.kt(新)— 隐式切换与互斥

```kotlin
package com.biosensor.migratedev.translation.cgm

import androidx.lifecycle.ViewModel
import androidx.lifecycle.ViewModelProvider
import androidx.lifecycle.viewModelScope
import com.biosensor.migratedev.decisioncore.cgm.CacheRecordDeduper
import com.biosensor.migratedev.decisioncore.cgm.CgmCommandPurpose
import com.biosensor.migratedev.decisioncore.cgm.CgmReadDecision
import com.biosensor.migratedev.decisioncore.cgm.CgmReadEvent
import com.biosensor.migratedev.decisioncore.cgm.CgmReadState
import com.biosensor.migratedev.decisioncore.cgm.CgmRecord
import com.biosensor.migratedev.decisioncore.cgm.CgmShortDecision
import com.biosensor.migratedev.decisioncore.cgm.CgmShortEvent
import com.biosensor.migratedev.decisioncore.cgm.CgmShortState
import com.biosensor.migratedev.orchestrator.WorkflowOrchestrator
import com.biosensor.migratedev.port.cgm.CgmPort
import com.biosensor.migratedev.translation.Translation
import java.util.UUID
import kotlinx.coroutines.flow.SharingStarted
import kotlinx.coroutines.flow.StateFlow
import kotlinx.coroutines.flow.combine
import kotlinx.coroutines.flow.stateIn

sealed interface CgmIntent {
    data object ReadCache : CgmIntent
    data object SyncTime : CgmIntent
    data object DeleteCache : CgmIntent
    // 无 Stop / ResetError:停止与复位是隐式机制(1.7 ③),不向 UI 暴露——
    // 用户点"对时"时若读活跃,内部先停读再对时;错误态自动复位,至多 toast
}

enum class CgmReadPhase { Idle, Sending, Receiving, Completed, Failed, Stopped, Error }

data class CgmShortResult(
    val purpose: CgmCommandPurpose, val ok: Boolean, val message: String
)

data class CgmUiState(
    val readPhase: CgmReadPhase,
    val readMessage: String?,
    val progressPoints: Int,          // 已接收 EIS 点数
    val roundCount: Int,              // 已接收完整轮数
    val recentLines: List<String>,    // 最近 10 条记录文本(数据看板)
    val shortResult: CgmShortResult?  // 最近一次短命令结果
    // 无可用态字段:按钮常亮可点,冲突由 submit 拒绝并 toast(1.7 ①②)
)

sealed interface CgmOutput {
    data class ReadCompleted(val path: String) : CgmOutput
    data class ShortDone(val purpose: CgmCommandPurpose) : CgmOutput
    data class Failed(val message: String) : CgmOutput
    /** 互转冲突:命令被拒,toast 提示等待(1.7 ②)。 */
    data class Blocked(val hint: String) : CgmOutput
}

/**
 * CgmTranslation:读流程与短命令各一个 orchestrator,互斥由 submit 检查。
 * ViewModel 生命周期 = 页面生命周期,旋转重建不销毁(见 11.4)。
 */
class CgmTranslation private constructor(
    private val deviceId: String,
    private val port: CgmPort,
    private val report: (CgmOutput) -> Unit
) : ViewModel(), Translation<CgmIntent, CgmUiState> {

    private val readOrchestrator = WorkflowOrchestrator(
        initialState = CgmReadState.Idle,
        decisionCore = CgmReadDecision,
        effectExecutor = port::execute,
        scope = viewModelScope,
        logTag = "Cgm.Read",
        onTransition = ::onReadTransition
    )

    private val shortOrchestrator = WorkflowOrchestrator(
        initialState = CgmShortState.Idle,
        decisionCore = CgmShortDecision,
        effectExecutor = port::execute,
        scope = viewModelScope,
        logTag = "Cgm.Short",
        onTransition = ::onShortTransition
    )

    override val uiState: StateFlow<CgmUiState> =
        combine(readOrchestrator.state, shortOrchestrator.state) { read, short ->
            read.toUi(short)
        }.stateIn(
            viewModelScope, SharingStarted.Eagerly,
            CgmReadState.Idle.toUi(CgmShortState.Idle)
        )

    // ── 互转策略(1.7 ②):submit 是通往 orchestrator 的唯一入口 ──
    // 冲突(任一侧活跃)→ 拒绝执行 + report Blocked(toast 提示等待),不隐式打断;
    // Error 态 → 自动复位后执行(复位无感,用户透明)。
    override fun submit(intent: CgmIntent) {
        when (intent) {
            CgmIntent.ReadCache -> startRead()
            CgmIntent.SyncTime -> startShort(CgmCommandPurpose.SYNC_TIME)
            CgmIntent.DeleteCache -> startShort(CgmCommandPurpose.DELETE)
        }
    }

    private fun startRead() {
        val short = shortOrchestrator.state.value
        if (short.isActive()) return blocked(short.hint())      // 短命令进行中:拒绝 + toast
        resetErrorIfNeeded()
        readOrchestrator.dispatch(CgmReadEvent.ReadRequested(newSessionId(), deviceId))
    }

    private fun startShort(purpose: CgmCommandPurpose) {
        val read = readOrchestrator.state.value
        val short = shortOrchestrator.state.value
        if (short.isActive()) return blocked(short.hint())      // 自身活跃(防连点):拒绝 + toast
        if (read.isActive()) return blocked(read.hint())        // 读活跃(昂贵操作):拒绝 + toast
        resetErrorIfNeeded()
        shortOrchestrator.dispatch(
            CgmShortEvent.ShortRequested(newSessionId(), deviceId, purpose))
    }

    private fun blocked(hint: String) = report(CgmOutput.Blocked(hint))

    /** Error 态自动复位(无 toast)。dispatch 同步入队单循环处理,先复位后开始。 */
    private fun resetErrorIfNeeded() {
        val read = readOrchestrator.state.value
        if (read is CgmReadState.Error) {
            readOrchestrator.dispatch(CgmReadEvent.ResetError)
        }
    }

    override fun onCleared() {
        readOrchestrator.close()
        shortOrchestrator.close()
    }

    // ── 上报(10.1):只报结论,不报过程 ──
    // 幂等转移(previous == current,如 Error 状态收到迟到确认)不是新结论,不上报——
    // 否则 Error/终态会因迟到事件反复上报同一条 Failed(施工 11 落实时发现的缺陷)。
    private fun onReadTransition(
        previous: CgmReadState, event: CgmReadEvent, current: CgmReadState
    ) {
        if (previous == current) return
        when {
            // 双闸门完成:Completed(带 filePath)经 FileWritten/AckReceived 第二闸 → Stopped
            previous is CgmReadState.Completed && current is CgmReadState.Stopped &&
                previous.filePath != null ->
                report(CgmOutput.ReadCompleted(previous.filePath))
            current is CgmReadState.Failed -> report(CgmOutput.Failed(current.reason))
            current is CgmReadState.Error -> report(CgmOutput.Failed(current.message))
            else -> Unit
        }
    }

    private fun onShortTransition(
        previous: CgmShortState, event: CgmShortEvent, current: CgmShortState
    ) {
        if (previous == current) return
        when (current) {
            is CgmShortState.Done -> report(CgmOutput.ShortDone(current.purpose))
            is CgmShortState.Failed -> report(CgmOutput.Failed(current.reason))
            else -> Unit
        }
    }

    private fun newSessionId(): String = UUID.randomUUID().toString()

    companion object {
        fun factory(
            deviceId: String, port: CgmPort, report: (CgmOutput) -> Unit = {}
        ): ViewModelProvider.Factory = object : ViewModelProvider.Factory {
            @Suppress("UNCHECKED_CAST")
            override fun <T : ViewModel> create(modelClass: Class<T>): T {
                require(modelClass.isAssignableFrom(CgmTranslation::class.java))
                return CgmTranslation(deviceId, port, report) as T
            }
        }
    }
}

private fun CgmReadState.toUi(short: CgmShortState): CgmUiState {
    val (phase, message) = toPhase()
    val eis = accumulated?.filterIsInstance<CgmRecord.Eis>() ?: emptyList()
    return CgmUiState(
        readPhase = phase,
        readMessage = message,
        progressPoints = eis.size,
        roundCount = eis.maxOfOrNull { it.seq }?.let { (it - 1) / 95 + 1 } ?: 0,
        recentLines = accumulated.orEmpty().takeLast(10).map { it.text },
        shortResult = short.toResult()
    )
}

/** 活跃判定与 toast 文案(1.7 ②:冲突拒绝时的提示)。 */
private fun CgmReadState.isActive(): Boolean = when (this) {
    is CgmReadState.Sending, is CgmReadState.Receiving, is CgmReadState.Completed -> true
    else -> false
}

private fun CgmShortState.isActive(): Boolean = when (this) {
    is CgmShortState.Sending, is CgmShortState.WaitingAck -> true
    else -> false
}

private fun CgmReadState.hint(): String = when (this) {
    is CgmReadState.Receiving -> "正在读取缓存中,请等待执行完毕"
    else -> "正在执行读取中,请等待执行完毕"
}

private fun CgmShortState.hint(): String = when (this) {
    is CgmShortState.WaitingAck, is CgmShortState.Sending -> "正在执行命令中,请等待执行完毕"
    else -> "正在执行命令中,请等待执行完毕"
}

private val CgmReadState.accumulated: List<CgmRecord>?
    get() = when (this) {
        is CgmReadState.Receiving -> accumulated
        is CgmReadState.Failed -> accumulated
        else -> null
    }

private fun CgmReadState.toPhase(): Pair<CgmReadPhase, String?> = when (this) {
    CgmReadState.Idle -> CgmReadPhase.Idle to null
    is CgmReadState.Sending -> CgmReadPhase.Sending to "命令发送中"
    is CgmReadState.Receiving -> CgmReadPhase.Receiving to "接收中(第 ${retryCount + 1} 次尝试)"
    is CgmReadState.Completed -> CgmReadPhase.Completed to "校验通过,落盘中"
    is CgmReadState.Failed -> CgmReadPhase.Failed to reason
    is CgmReadState.Error -> CgmReadPhase.Error to message
    is CgmReadState.Stopped -> CgmReadPhase.Stopped to null
}

private fun CgmShortState.toResult(): CgmShortResult? = when (this) {
    is CgmShortState.Done -> CgmShortResult(
        purpose, ok = true,
        message = if (purpose == CgmCommandPurpose.SYNC_TIME) "对时成功" else "删除成功")
    is CgmShortState.Failed -> CgmShortResult(CgmCommandPurpose.SYNC_TIME, ok = false, message = reason)
    else -> null
}
```

说明:

- **互转策略的落实(1.7)**:UI 按钮常亮可点(①);submit 是唯一入口,冲突(任一侧活跃)→ 拒绝 + `report(CgmOutput.Blocked)` toast 提示等待,Error 态自动复位后执行(②);状态机对不合法事件幂等忽略(③)。`StopCurrent` 保留在词汇/转移表中(程序化停止入口,如未来 Root 需要),当前 UI/Translation 不产生它;`ResetError` 只由 Translation 内部 dispatch
- **拒绝不打断的时序保证**:冲突时**不** dispatch 任何事件,旧命令 flow 继续跑完;Error 复位时 `dispatch` 同步入队单循环顺序处理——先 `ResetError`(变 Idle)再开始,不会并发
- **蓝牙层防御**:通道消费权转移保留为防御机制(3.3)——即使未来放行切换(绕过 Translation),新命令 flow 也会夺权结束旧 flow,不会双命令并发收集
- **sessionId 在此生成**(UUID),reduce 保持纯函数
- **旋转不丢数据**:CgmTranslation 是 ViewModel,由 RootWorkflow 的 ViewModelStore 持有;Activity 重建(旋转)时 ViewModelStore 保留,Translation 与两个 orchestrator 存活,`uiState`(StateFlow)数据不丢;Screen 纯呈现,旋转后重新 collect 即完整恢复。**数据只存在两个地方:StateFlow(展示)与 State 内 accumulated(会话数据),均随 ViewModel 存活**——这是现有 Auth/Connection 同款机制

**旋转不丢数据——机制说明(重要)**:屏幕旋转会重建 Activity 与 Composable 树,但 **`CgmTranslation` 是 ViewModel,活在 RootWorkflow 的 `ViewModelStore` 里,与 Activity 生命周期解耦**。全部数据只存在于:

1. `uiState: StateFlow<CgmUiState>`(orchestrator.state 投影)——StateFlow 的 value 在 ViewModel 内存中,旋转不销毁
2. `CgmReadState.Receiving.accumulated`(会话原始记录)——状态机 State,同样在 ViewModel 内存中

旋转后新 Screen 只是重新 `collectAsStateWithLifecycle`,从 StateFlow 拿到完整状态(包括进行中的读取、累积的点数、短命令结果)。**不需要 rememberSaveable、不需要序列化**——这是"数据在 ViewModel、UI 只投影"的直接收益。唯一注意:Screen/组件内不得持有业务数据(输入框等纯 UI 状态用 rememberSaveable 即可,本页面没有这类状态)。

### 11.8 性能与防抖(评审第 4 点)

疑点:"流式上行实时展示,不能掉帧;看板默认收起、点击展开不能有延迟;展开后列表变长、收起后变短,位置计算不能卡在旧长度上。"

逐条对策,前三条是**架构层内建**的,不靠额外代码:

1. **高频更新不积压:StateFlow conflate 内建节流**。数据上行路径是 `RecordsProduced` → reduce(状态更新)→ `combine` 投影 → `collectAsStateWithLifecycle`。`StateFlow` 只保留最新值,`collectAsStateWithLifecycle` 同为 conflate 收集——字节块高频到达时,中间的投影值被丢弃,UI 永远只重组一次到最新状态,**不会堆积中间帧**(这是框架层保证,不需要自写防抖器)。数据块到达越密集,合并效果越明显。
2. **投影只含展示量,重组成本恒定**。每次投影重建的是:几个 Int/Enum + `takeLast(10)` 短字符串(≤10 条 × ~30 字符)——不随累积总量增长,不重建大列表。`accumulated` 在状态机里是全量 List,但投影到 UI 的永远是常量小量。
3. **展开无延迟,位置不错位**。记录一直在 ViewModel 的 `accumulated` 里(旋转都不丢,见 11.1)——"展开"只是把已有数据渲染进组合树,没有拉取/等待过程,点击即见。收起 = `if (expanded)` 条件组合(LazyColumn 从组合树移除);展开 = 重新组合,Compose 按当前内容**重新测量**,不会残留旧高度(收起前很长、展开后很短仍按新数据布局,不存在"卡在旧长度"——条件组合而非 `Modifier.height` 固定/`alpha(0)` 隐藏,后者才会留布局残影)。
4. **滚动跟随仅当展开时**。展开态下跟随最新数据:用 `rememberLazyListState()` + `LaunchedEffect(roundCount) { if (expanded) listState.scrollToItem(recentLines.lastIndex) }`——新数据到达自动滚到底部;收起时 LaunchedEffect 不触发,零开销。
5. **生产侧开销可控**。解析管道每块字节只做一次解码 + 切行 + 逐行正则匹配(单行 EIS ~30 字符,一个 Regex);累积 append 是 List 的 O(1) 摊销;END 到达后全量校验一次 O(n)(n≈5000 行,主线程几毫秒,可接受)。不存在逐字节级操作。
6. **短命令结果与看板互不影响**:`combine` 只在任一状态变化时重新投影,对时结果(shortOrchestrator)与数据流(readOrchestrator)各自触发,不会互相拖动重绘。

实施时验证点(第 7 步端到端):接收 30 秒数据流,观察重组帧率(Profile GPU Rendering / Baseline Profile);展开-收起-展开循环 20 次,确认无布局错位;旋转后展开态与滚动位置的行为(rememberSaveable 的 expanded 保留,滚动位置可接受重置)。

|---|---|
| 01 父子编排器(控制/展示生命周期分离) | 解析管道在 effect flow 内(控制侧),UI 展示只收状态机投影——展示生命周期与会话生命周期解耦 |
