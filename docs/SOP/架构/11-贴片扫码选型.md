## 3. 逐库事实

### 3.1 zxing-cpp(主选候选)

- **坐标与形态**【官方】:`io.github.zxing-cpp:android:3.1.1`,已上 **Maven Central**(非 JitPack;JitPack 上的 `cooldudezach/zxing-cpp` 是第三方 fork,勿用)。是 zxing-cpp 仓库的官方 Android 模块(JNI + CMake)。
- **体积实测**:AAR 2,944,658 B;内含 `.so` 按 ABI 拆分(arm64-v8a ≈1.63 MB / armeabi-v7a ≈1.15 MB / x86 系各 ≈1.7 MB);`classes.jar` 仅 24 KB(Kotlin API `zxingcpp.BarcodeReader`)。
- **相机**:不自带预览,`api androidx.camera:camera-core` + 直接吃 `ImageProxy` / `Bitmap` —— 与 Compose + CameraX 天然契合。
- **能力**:官方 README 明确 **Thread safe**;解码选项有 `tryInvert`(反色码)、`tryRotate`、`tryHarder`、`tryDownscale`、多二值化算法、`formats`、`isPure`;码制比 Java 版多 **Micro QR、rMQR、DataBar 全系、Telepen**(Java 版没有);含 **GS1** 相关格式与 HRI 输出模式(源码确认) —— 若贴片码走 GS1 体系,这一条直接省事。
- **工程性**:`minSdk 21`;CMake 带 `-DANDROID_SUPPORT_FLEXIBLE_PAGE_SIZES=ON`(**Android 15+ 的 16 KB page size 合规**,加分);`-DZXING_WRITERS=OFF`(纯解码,不引入写码依赖,许可负担干净);License **Apache-2.0**(POM + 仓库双确认)。
- **短板**:①原生 so 是体积大头;②**预览、扫码框、权限、生命周期全要自己写**;③CNN 超分方案(华为/商业 SDK)在极端困难码上仍更强。

### 3.2 华为 Scan Kit(备选)

- **坐标**【官方】:`com.huawei.hms:scan`(标准)/ `scanplus`(增强),仓库 `https://developer.huawei.com/repo/`(**不在 Maven Central / Google Maven**)。
- **无 GMS 可用**:不依赖 GMS 任何组件【官方】;**也不需要华为设备**(SDK 1.1.0.300 起支持非华为机)【转述】。装了 HMS Core 4.0.0+ 用其算法,未装则用 **SDK 内置模型,"功能不受影响"**【转述】—— 这正是它对离线场景友好的地方。
- **体积**:AAR 实测 scan 1.25 MB / scanplus 3.53 MB;scanplus 多出的 2.3 MB 全是识别增强模型(`detect.ms` / `corner.ms` / `angle.ms`)。官方口径 ≈1.1 MB / ≈3.1 MB,与实测吻合。**官方明确:非华为设备上做多码建议用 scanplus**【转述】。
- **收费**:官方 FAQ **"采用 SDK 方式调用不收费"**,scanplus 亦可免费商用【转述】。纯端侧,官方称"不涉及云端功能,不保存任何个人数据"【转述】。
- **前提**:注册华为开发者账号 + 实名认证 + 在 AGC 建项目添加应用;**官方未把"上架华为应用市场"列为前提**。
- **风险**:①引入 `com.huawei.hms` 依赖树,需在 `settings.gradle` 加华为仓库,并与其它 HMS 服务(推送/地图)做版本锁定,避免冲突【社区】;②第三方应用商店上架可能被提示"含其他厂商组件"【社区,非官方条款】;③官方宣传的识别率数字(99.8% vs ZXing 95.2% 之类)**全部出自博客,无官方 benchmark,不可引用**;④官方未宣称提供 **GS1 AI 解析**(医疗 UDI 需自己做)。

### 3.3 ML Kit:三条路径要分清

| 路径 | 能否在无 GMS 机上用 | 官方原文 | 结论 |
|---|---|---|---|
| 捆绑版 `com.google.mlkit:barcode-scanning:17.3.0` | **可能可以,但无官方背书** | 只说 "statically linked to your app at build time"、"Model is available immediately" | **没有任何一句"不依赖 Google Play Services"**;POM 里反而传递依赖 `play-services-basement:18.4.0` 与整个 thin 库 → 必须真机自测 |
| 服务版 `play-services-mlkit-barcode-scanning:18.3.1` | **不能** | "Model is dynamically downloaded via Google Play Services" | **首用需联网下载,下载完成前的请求静默返回空结果** —— 医疗场景不可接受 |
| Google Code Scanner `play-services-code-scanner:16.1.0` | **不能** | "The implementation resides entirely within Google Play services" | 华为/荣耀上有大量崩溃与 `CODE_SCANNER_UNAVAILABLE` 实证【社区】;且**只返回一个码、UI 不可定制、无连续扫描**,不符合贴片连续扫的需求 |

补充事实:三者都要求 **API 23+**;捆绑版官方口径 APK 净增 **≈2.4 MB**(AAR 9.9 MB 是含全 ABI 与未收缩资源的原始件,不是装机增量);**不需要 Firebase、不要求 Play 上架**;但条款要求 **app 自行在隐私政策中披露 ML Kit 回传的性能指标**("ML Kit APIs also send metrics about the performance and utilization"),端侧处理图片本身不上传。

### 3.4 ZXing Java 系:能跑,但别当主力

- `com.google.zxing:core:3.5.4`(2025-11-11):纯解码内核,596 KB,POM 无任何 runtime 依赖(确认不需要 GMS);字节码 major 52(Java 8),只引用 `java.io/math/net/nio.charset/text/util`,**minSdk 24 可直接用**(且本工程 `coreLibraryDesugaringEnabled true` 本就开着)。
- 但 README 自述**已进入维护模式(仅接受补丁、无 roadmap)**;公开困难图基准中识别率明显落后(见 §4)。
- `com.journeyapps:zxing-android-embedded:4.3.0`:封装好用(`ScanContract` 三行接入),但**事实停更**(master 末次提交 2022-10,127 个 open issue),**Camera1**(字节码确认 `android/hardware/Camera` 引用 74 处、`androidx.camera` 引用 0 处),且带着几个没人修的坑:
  - `#762` Android 14+ StrictMode `IncorrectContextUseViolation`(open,0 回复);
  - `#763` Android 16 大屏忽略方向/尺寸限制 —— 根因是**库自身 manifest 硬编码 `CaptureActivity` 为 `sensorLandscape`**,Google Play 会就此发合规提醒;
  - `#740` Android 12+ 自动对焦失效(open)。
  - 另:库 manifest **自带 CAMERA 权限**并用 Fragment/ActivityResult 契约,与我们单 Activity + Compose 的形态并不贴合。
- `com.github.yuriy-budiyev:code-scanner:2.3.2`:MIT、82 KB、Camera1,**仅在 JitPack**、2022 年后无新版本 —— 单点风险高于收益。

### 3.5 已排除的路线

- **腾讯云智能扫码 IS**:能力对口(端侧离线、支持 DataMatrix、专治"大图小码/一图多码"),但 **Android 仅支持 `armeabi-v7a`,arm64 官方称"在规划中"**【转述】—— 对 2026 年的新 app 是硬伤;且 **50,000 元一次性买断、绑定包名 + 签名 SHA1 不可修改、授权需首次联网**【转述,下单前务必向腾讯云核实】。
- **OpenCV `wechat_qrcode`**:①**官方 `org.opencv:opencv:5.0.0` AAR(153 MB)里根本不含该模块**(实拆 `classes.jar` 确认,`objdetect` 只有 `QRCodeDetector`),要用必须自编译 opencv_contrib;②官方路线 OpenCV 5.0 已把模型从 Caffe 换成 **ONNX**,而 `modules/wechat_qrcode/CMakeLists.txt` 仍在下载 `.caffemodel`(已知不一致,自编译会踩);③封装版单 ABI ≈10.5 MB(jenly 2.6.0,要求 compileSdk ≥35),是本次所有方案里最重的;④**只做二维码,完全不支持 DataMatrix 与一维码** —— 医疗 UDI 场景直接出局;⑤学术多数据集评测中在 SE-Barcode 上被 zxing-cpp 反超(WeChat 47.7% vs zxing-cpp 85.8%),"微信引擎全面更强"是站不住的。
- **百度 / 阿里**:均为**云 API 路线**(阿里部分收费能力 2025 年起陆续下架),不适合端侧离线扫码。
- **商业 SDK**:Scandit(唯一把 **GS1 MODE** 做成产品能力、有医疗器械案例,需询价)、Dynamsoft(官网 **$1,499/年起**,可申请纯离线 license)、Honeywell SwiftDecoder(经销商有公开挂牌价,支持全部 GS1 码制、每帧最多 50 码)、Scanbot(扁平年费,100% 端侧)、Zebra DataWedge(仅 Zebra 硬件,免费随设备)。**Cognex cmbSDK**:多方第三方称 2025-09-30 后停售停支(未找到 Cognex 官方公告)→ 不建议新项目选型。商业路线仅当"识别率/破损码/GS1 解析"成为硬验收指标时才进入。

## 4. 识别力:有数字的部分

| 基准 | 数据集 | 结果 | 性质 |
|---|---|---|---|
| Dynamsoft QR 基准(含 ZXing Java 3.5.1) | 536 张真实困难图 / 1232 个 QR / 16 类困难场景 | Dynamsoft 83.29% > BoofCV 60.69% > WeChat 48.89% > **ZXing 31.87%**;ZXing 均耗 179.57 ms/图 | 竞品厂商自测,**有偏倚**,但含具体数字与场景拆分 |
| Dynamsoft PDF417 基准(含 zxing-cpp 与 ML Kit) | 88 张真实 PDF417 | ML Kit **61.36%** @304 ms;**zxing-cpp 52.27% @127.56 ms(最快)** | 同上 |
| Kazuhito00 合成 QR 基准(含 zxing-cpp) | 780 张 / 65 场景 / 12 类数据 | **zxing-cpp 93.3%(728/780)@92.8 ms,第一名**;wechat-qr 87.6%;opencv-qr 51.8% | 第三方开源基准 |

**诚实声明**:①反色码、屏幕码、破损码**没有**任何包含 "Java ZXing vs zxing-cpp vs ML Kit" 三方同数据集的公开评测 → 这部分**未查到**;②各库"R8 收缩后的 APK 净增体积"厂商均未公布 → 表中给的是**构件原始体积**;③所有小码能力都受一个共同约束:**ML Kit 官方要求最小编码单元 ≥2 px**,EAN-13 需图像宽 ≥190 px —— 换句话说,**"扫不出小码"的第一大原因不是库,而是 CameraX `ImageAnalysis` 默认 640×480 太低**(社区大量实例),必须显式提到 1280×720 / 1920×1080。

## 6. 接入形态(若采纳,供评审)

沿用本仓库既有分层,引擎关在适配器里,换 SDK 只改适配器:

```text
UI(ScanScreen/ScanRoute) → Translation(ScanTranslation) → DecisionCore(ScanState)
                                   ↓ effect
                          ScanPort.execute(ScanEffect): Flow<ScanEvent>   ← 契约
                                   ↓ 实现
              ZxingCppScanAdapter / HuaweiScanAdapter / FakeScanPort(测试)
```

- **契约建议**:`ScanEffect.StartScan / StopScan / Torch(on/off) / Retry`,`ScanEvent.CameraReady / CodeDetected(raw, format, bbox) / ScanFailed(reason) / Stopped`;原始码串**不做业务解析**(SN / GS1 拆分另起一层,见 §7)。
- **权限门**:参照 `migratedev/src/main/kotlin/com/biosensor/migratedev/ui/connection/BluetoothAccessGate.kt` 的形态加 `CameraAccessGate`(拒绝 → 说明页 + 跳系统设置;不再"静默无反应")。
- **Manifest**:新增 `<uses-permission android:name="android.permission.CAMERA" />` 与 `<uses-feature android:name="android.hardware.camera" android:required="false" />`(扫码非主功能,`required=false` 以免商店过滤掉无相机设备)。
- **UI**:单 Activity 内新增 Compose 路由 + `AndroidView(PreviewView)` / 库 View;扫码页进入即申请权限、离开即 `unbind`(对齐现有连接页的可见性驱动写法)。
- **落点**:贴片扫码的产物大概率要接**设备绑定**(见 [../需求/05-设备绑定.md](../需求/05-设备绑定.md))—— 扫到的标识 → 绑定表 → 连接页按绑定自动连接。
- **测试**:沿用现有 `Fake*Port` 模式做纯 JVM 单测(虚拟时间 + 冷流重放),"解码正确性"用**固定图片样本**做 instrumented 测试。

## 7. 代价与风险

| 项 | 内容 |
|---|---|
| 体积 | zxing-cpp ≈2.9 MB AAR(单 ABI 分拆后装机更小);scanplus 3.53 MB;ML Kit 捆绑 +2.4 MB。需与产品确认包体预算 |
| 权限与隐私 | 新增 CAMERA 权限 → 隐私政策、应用商店权限说明、等保/医疗器械软件文档需同步(本仓库目前**零相机权限**,是个干净的起点,别加得随意) |
| 合规 | ML Kit 会回传性能指标,医疗类需法务确认披露口径;华为/腾讯方案需确认"引入第三方厂商组件"在目标渠道无阻碍 |
| 厂商 ROM 坑 | 社区实测:改 `setTargetResolution` 反而导致某些机型(Pixel 2XL)完全不识别且不自动回退;三星 A23 需显式指定分辨率。**新代码用 `ResolutionSelector`/`ResolutionStrategy`,不要用已废弃的 `setTargetResolution`**;全流程务必 `STRATEGY_KEEP_ONLY_LATEST` + 在 `OnCompleteListener` 里 `close()` ImageProxy(不做会慢 2–15 秒) |
| 识别稳定性 | 官方明确建议等**连续多帧同值**再判定成功,避免误读;缺静默区(白边)也会导致失败 |
| 若贴片码是 GS1 DataMatrix | 主流 2D 载体,但**AI 字段拆分(DI/PI:批号 10 / 生产日期 11 / 失效期 17 / 序列号 21)所有候选都不提供**,需另接 **GS1 Syntax Engine**(原生 C 库 + Java/C# 绑定,有官方 Android 示例,permissive 许可可闭源内嵌;确切 SPDX 名与最新版本号未查到)。相关标准:《医疗器械唯一标识系统规则》(2019 年第 66 号公告)、**YY/T 1942—2024**、YY/T 1681—2019;北京药监局问答特别提示"若扫出来只是长串字符、未按 AI 分开,需确认扫码设备是否处于 GS1 解析模式" |

## 8. 待确认(需要产品/硬件侧回答)

1. **贴片上的码是什么码制、什么尺寸、印在哪**(纸标/金属/曲面/覆膜反光)?这直接决定要不要上增强模型 —— 也是本调研唯一的需求缺口,现有文档(需求清单、连接流程)均**未提及贴片扫码**。
2. 码里编码的是**什么**(SN / MAC / GS1 DI+PI / 自定义)?是否有厂商私有格式或加密?
3. 扫码的**业务目的**:绑定设备、录入耗材/试纸批号、还是溯源?
4. 目标机型范围(华为/荣耀占比)、是否要求上架应用商店、**是否上架 Google Play**?
5. 包体预算与是否接受引入 HMS 依赖树。
6. 最低可接受识别率与允许的扫码耗时(定验收线,而不是"能扫就行")。

## 9. 验证清单(PoC 阶段)

- [ ] 真机在**真实贴片**上扫码成功率(最差光照 / 最脏 / 最小批次各 20 次),记录耗时分布
- [ ] 无 GMS 机型(华为/荣耀/鸿蒙)各一台跑通,确认无崩溃、无静默失败
- [ ] 反色/覆膜反光/曲面等实例是否可解(必要时开 `tryInvert` / 多二值化)
- [ ] CameraX 分辨率与预览坐标系正确(预览框与识别区一致),`STRATEGY_KEEP_ONLY_LATEST` 已设、ImageProxy 已 close
- [ ] 冷启动到首帧可扫的时间(离线、飞行模式)
- [ ] 体积增量实测(`analyze` APK / AAB 前后对比)
- [ ] 权限拒绝 / 无相机 / 后台切换 / 旋转 / 来电打断等边界
- [ ] 若走 GS1:码串 → AI 拆分 → HRI 输出全链路正确
