# 词汇表

> 说明：全库统一词汇。新读者先读这里；写代码/文档必须使用本表词汇。
> 词汇变更必须走设计文档（如 04-词汇统一与契约收尾），不能顺手改。

## 1. 活跃词汇

| 词汇 | 归属 | 含义 |
|---|---|---|
| `State` | decisioncore | 工作流当前状态（sealed interface + data object/class） |
| `Event` | decisioncore | 驱动状态变化的事件，来自 UI 或 Port |
| `Effect` | decisioncore | 状态机要求执行的副作用描述，不直接做 IO |
| `Intent` | translation | UI 提交的用户意图 |
| `UiState` | translation | 提供给 UI 的呈现状态 |
| `Output` | translation | 跨业务域上报的事实（Authenticated、LogoutRequested…） |
| `Orchestrator` | orchestrator | 事件循环 + 副作用执行器；参数 `effectExecutor: (Effect) -> Flow<Event>`（函数类型） |
| `DecisionCore` | decisioncore | `reduce(state, event) -> Transition(newState, effects)` 纯函数状态机 |
| `Translation` | translation | ViewModel 薄层：Intent/State 翻译 + 子 Orchestrator 持有者 |
| `Port` | port | 接口形态 `execute(effect): Flow<event>` + 直读流；业务端口或能力端口 |
| `RootWorkflow` | orchestrator/root | 父编排器，管理子业务生命周期与页面栈 |

## 2. 已删除词汇（历史沿革）

| 词汇 | 去向 | 说明 |
|---|---|---|
| `Command` | → `Effect` | 曾是"Orchestrator 翻译给 Port 的命令"；后来删除翻译环节，effect 直通 |
| `Result` | → `Event` | 曾是"Port 返回的结果"；统一为 event 流，翻译止步于端口边界 |
| `CommandPort` | 删除 | 泛型执行器接口被函数类型 `(Effect) -> Flow<Event>` 取代 |
| `BluetoothCommand` / `BluetoothResult` | → `BluetoothEffect` / `BluetoothEvent` | 能力端口词汇形态统一（语义不变） |

## 3. 命名规则

- 业务词汇形态统一：`XxxEffect` / `XxxEvent` / `XxxState` / `XxxIntent` / `XxxUiState` / `XxxOutput`。
- 端口：业务端口 `XxxPort`（auth、connection）；能力端口放 `port/adapter/<能力>/`。
- 文件/目录：中文命名（本文档体系），代码标识符英文。
