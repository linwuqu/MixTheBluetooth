## 3. 沉淀顺序与文档结构

1. 需求提出 → 对话对齐（不写文档）。
2. 架构阐述与迭代（过程文档，施工后退役）。
3. 施工完成后：沉淀业务说明书到本目录（模板见 doc-writer skill）。

每篇工作流文档的结构（让读者一屏看懂，再展开细节）：

1. **0. 概览**（先读，控制在一屏内）：
   - 0.1 这部分做了什么（目标）
   - 0.2 基础思路（蓝图：尽量少的语言 + 一张图，让外行人脑中有基本框架）
   - 0.3 痛点与演进（------> 逐个改进，每行一个痛点 → 改进 → 状态）
   - 0.4 项目切面（覆盖的文件树与相关文档路由）
   - 概览每块标注"详见 第 N 章"，可直接点击路由
2. **基础思路详解**：该业务都有的 MVVM 骨架（Intent / State / Event / Effect / UiState 的设计）。
3. **改进点详解**：每个改进点一节，与 0.3 痛点一一对应。
