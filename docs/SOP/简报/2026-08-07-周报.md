# 周报简报

2026-08-07

## 本周主要做的事情

1. 架构上的变动：
   - AppGraph依赖挂载整理成能力端口形式：一开始的设计并没有想的很通用 所以在依赖挂载的时候会出现标定远端能力时首先需要实例化Account对象 才能实例化远端port 这并不是很合乎逻辑 整理思路以后确定了能力挂载和业务组装 在能力挂载部分只标定能力（包括本地加密键值对、本地数据库、本地文件管理、远端http、ble蓝牙） 业务组装时只明确依赖哪些能力 如鉴权业务需要kv http能力 扫描连接业务需要sqlite ble能力 cgm缓存数据流处理业务需要ble file能力 同时针对于http具体需要哪些端点 这个在业务中自行确认 端口只负责统一的超时等异常上报和能力execute 实现了能力与业务的分离性
   - 约化了Effect->Command的转换 但是保留了Result->Event的转换：前者为下达指令 后者为上报回复 对于编排器与port端口之间的沟通实质上并不需要下达指令时的翻译 只需要上报回复时过滤掉上层透明的底层信息即可 这一改动减少了多余的转换 提高了整体逻辑的通顺度
   - UI 块级展示：原先的UI控制与界面混在一起 同时不能预览 导致了compose代码整体可读性不高 现在做了块级独立 在screen中首先看到的是compose块的罗列 这样可以快速的定位出界面结构 然后对于每一块具体是怎么表现的可以单独查看对应文件 同时明确了UI控制放在Route 界面放在Screen的设计语言

2. 缓存明文流初步讨论 这一部分环节之间的衔接性很紧密 这里只是给出初步的思路 还需要不断地调试和打磨
   - 首先明确任务边界：把"设备缓存"完整搬到 app 本地文件:向设备发三条指令(同步时间 / 读取缓存 / 删除缓存),接收设备回放的缓存数据,解析成结构化记录,校验完整性(优先用结构连续性,marker 兜底),通过后确认删除设备缓存(EEPROM 容量有限),数据落盘形成文件。
