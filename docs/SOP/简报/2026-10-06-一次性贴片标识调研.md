# 血糖传感器贴片方案

日期：2026-10-06。版本：V4。状态：设计方案已整理；App 和固件尚未实现。

## 1. 采用方案

使用 **Data Matrix、版本化贴片结构、本地绑定表和轮次归档**。

工厂在贴片上完成印码或贴标。用户在 App 中扫码启用。App 保存贴片与设备的绑定。App 将绑定信息附加到每轮传感器数据。没有网络时，App 先保存本地记录。网络恢复后，App 再上传记录。

| 项目 | 决定 |
|---|---|
| 码制 | 私有 Data Matrix ECC 200 |
| 码内信息 | 编号、型号、批次、日期、使用时长、校准引用和扩展字段 |
| 绑定单位 | 一枚贴片对应一个使用周期；一个周期包含多轮测量 |
| 文件格式 | 保留原始记录；在每轮 summarize 后追加 PATCH_META |
| 试制标识 | 600 dpi 热转印打印，加定位工装 |
| 量产标识 | 工厂自动贴标、视觉回读和不良品剔除 |
| 当前协议 | App 首次批量确认轮次，重复回放恢复原绑定 |
| 量产协议 | 固件返回 measurementId 与 useId，自动确认轮次归属 |

## 2. 对象与关系

| 名称 | 标识 | 固定含义 |
|---|---|---|
| 贴片 | patchId | 一枚实体耗材 |
| 设备 | deviceId | 提供蓝牙数据的硬件 |
| 使用周期 | useId | 某账号在某设备上使用某枚贴片的周期 |
| 测量轮次 | roundId | 一组 EIS、CA 和 summarize |
| 读取会话 | sessionId | App 的一次缓存下载 |

```text
账号＋设备＋贴片 → 使用周期 → 多轮测量 → 各测量点
```

这些标识不得混用。一次缓存下载可以包含多轮历史测量。一枚贴片也可以多次下载数据。

现有数据样例有三种情况：seq 在各段内重新开始；同一轮数据重复回放；尾段缺少 summarize。因此，App 不能只按 seq、接收时间或下载会话判断贴片归属。

## 3. 码制与贴片信息

### 3.1 使用 DM 的原因

DM 的最小白边为一个模块，普通 QR Code 为四个模块。DM 适合面积有限的标签。ECC 200 可以纠错。医疗产品识别已有成熟的 GS1 DataMatrix 规则。[GS1 指南](https://ref.gs1.org/guidelines/datamatrix/)、[白边要求](https://ref.gs1.org/guidelines/2d-in-retail/)

本期使用私有 DM，不把它当成已完成的医疗器械 UDI。

DM 与私有二进制包可以减少用户直接查看明文的情况。但“微信扫不出”不能作为安全承诺。腾讯官方扫码服务列出 DM 支持。[腾讯说明](https://cloud.tencent.com/document/product/1214/42829)

码内不放用户信息、血糖记录或校准系数。校准只放引用编号。生产工具生成数字签名。App 可以离线验证签名。签名用于检查数据是否被修改。签名不隐藏码内信息。

### 3.2 使用可扩展结构

```kotlin
import java.time.LocalDate

data class PatchInfo(
    val schemaVersion: Int,
    val patchId: String,
    val modelId: Int,
    val lotNo: String,
    val manufacturedOn: LocalDate,
    val expiresOn: LocalDate,
    val maxUseMinutes: Int,
    val calibrationRef: String,
    val extensions: Map<Int, ByteArray>,
)
```

patchId 在生产时生成。modelId 用于检查兼容性。lotNo 和 calibrationRef 随测量归档。extensions 保留新字段。

印刷包采用“固定头部＋带编号字段＋厂商签名”。App 读取 rawBytes。旧 App 可以跳过可选扩展；不认识关键字段时拒绝启用。

包长、字段编号和验签规则见[编码协议](./附件/2026-10-06-贴片编码协议.md)。

### 3.3 加入两种期限

库存期限由 expiresOn 表示。使用期限由 maxUseMinutes 表示。两者都来自生产放行记录。

App 启用贴片时保存 activatedAt。截止时间采用以下较早值：

```text
库存有效期日结束
activatedAt＋maxUseMinutes
```

重扫、重连和重启不得重置期限。过期片不能启用。已用片不能再次启用。

到期后，App 保留原始数据和历史导出。新的测量标为超期，不标为有效使用数据。手机时间明显回退时，App 停止新激活并要求校正日期。

## 4. 打印与生产

用户收到已贴标产品。用户不承担逐枚打印和贴标。

| 阶段 | 设备与工序 |
|---|---|
| 实验室打样 | TSC TX610 600 dpi、剥离器、定位工装 |
| 小批试制 | 卷式标签、半自动贴标机构、贴后回读 |
| 正式量产 | 自动印贴、视觉逐枚回读、不良品剔除、包装核对 |

TX610 的官方规格包含 600 dpi，系列提供剥离选项。量产设备以 cab HERMES Q2 600 dpi 加贴标头作为选型基准。[TSC 规格](https://usca.tscprinters.com/en/products/tx-series-4-inch-performance-desktop-printers)、[cab 自动印贴](https://www.cab.de/en/marking/print-apply/hermesq/)

连续卷材贴片先在外侧膜片印码或贴标，再模切复合。独立成品使用输送治具自动贴标。两种工艺使用同一编码协议。

生产 SOP 固定为：

1. 生产工具生成贴片编号。
2. 签发工具生成码包。
3. 打印机连续打印。
4. 贴标设备贴到指定位置。
5. 视觉设备逐枚回读。
6. 系统比对签发记录。
7. 产线剔除不合格品。
8. 包装工位核对内外编号。

包装可印同一贴片的副本码。副本表示同一件产品，不表示第二枚贴片。打开包装后，贴片仍须保留可扫描位置。

首轮样张指定：160 字节包上限、16×16 mm 码区、600 dpi、每模块 6 点、四周 2X 白边、哑光白底黑码。面材和碳带必须匹配。胶黏剂、清洁工序、汗液和曲面读取一起验证。

产能按整线合格产出验收。不能用打印机走纸速度代替贴片产能。单片成本包含标签、碳带、设备摊销、人工、检测和报废。

## 5. App 绑定与脱机使用

### 5.1 App 入口

在现有 CGM 页增加贴片信息卡。提供“扫码启用”和“更换贴片”。

扫码页作为 CGM 内的子页面。返回时关闭扫码页，不退出 App。

### 5.2 首次启用

1. 用户通过现有连接页连接设备。
2. 用户在 CGM 页点击“扫码启用”。
3. App 解析码包并验签。
4. App 检查型号、期限和使用记录。
5. App 读取旧缓存，保存轮次基线。
6. 用户核对贴片编号、批次和期限。
7. App 保存使用周期。
8. App 显示启用成功。

启用成功后，用户按设备现有方式开始测量。当前仓库没有已核实的测量启动命令；本期不新增假定的 START 指令。

### 5.3 轮次确认

旧缓存基线内的轮次不自动归给新贴片。

首次收到的新完整轮次进入批量确认页。用户一次确认多轮，不逐个标注 EIS 或 CA 点。

已确认轮次保留原 useId。重复回放自动恢复原归属。未确认轮次显示“待关联”。缺少 summarize 的轮次显示“未完成”。

当前蓝牙数据没有贴片编号。因此，本期采用批量确认。量产固件返回 useId 后，App 才能可靠自动关联手机不在场时采集的数据。

### 5.4 更换贴片

用户先结束当前硬件测量。App 再读取并归档旧数据。用户最后扫描新片。

App 在一个事务中结束旧周期并启用新周期。失败时保留旧状态。每台设备最多有一个 ACTIVE 周期。

重复扫描当前贴片时，App 显示已有周期。扫描已结束贴片时，App 拒绝重新启用。

### 5.5 脱机规则

| 条件 | App 动作 |
|---|---|
| 首次安装，无本地身份 | 要求联网登录一次 |
| 已验证账号，无网络 | 允许扫码、绑定、读取和归档 |
| 网络 token 到期 | 保留本地采集；上传前重新认证 |
| 验签公钥未知或签名失败 | 拒绝启用 |
| 蓝牙掉线 | 保留 useId，重连后恢复 |
| App 重启 | 恢复 ACTIVE 周期和截止时间 |
| 网络恢复 | 上传待同步队列 |
| 跨手机重复用片 | 标记冲突，保留数据与归属证据 |

本地采集身份放入现有 TinkKvStore。它与七天网络 token 分开。断网不能停在当前的远端验证页面。

脱机只能立即检查本机复用。跨机复用由量产固件的激活记录与服务端唯一约束共同处理。

## 6. 绑定表与数据文件

### 6.1 建立四张新表

保留 deviceBinding。新增以下表，全部放入现有 migratedev.db。

| 表 | 保存内容 | 约束 |
|---|---|---|
| sensorPatch | 贴片编号、产品字段、原始码包 | patchId 唯一 |
| patchUse | 账号、设备、贴片、启用时间、截止时间、状态和基线 | 每片一个周期；每设备一个 ACTIVE |
| measurementRound | 轮次身份、原始数据位置、useId 和归属快照 | 重复回放不新建轮次 |
| syncOutbox | 待同步事件和重试状态 | eventId 唯一 |

轮次与使用周期的账号、设备必须一致。业务查询按账号过滤。换账号不转移旧数据。

保存信息快照。以后型号资料更新，不改写旧测量的批次、期限或校准引用。

完整表结构见[绑定表 SQL](./附件/2026-10-06-贴片绑定表.sql)。

### 6.2 在 summarize 后追加元数据

```text
LOG:...        本轮 EIS 段
EIS:...
LOG:...        本轮 CA 段
CA:...
summarize:<设备原文>
PATCH_META:<本轮单行 JSON>
LOG:...        下一轮开始
```

PATCH_META 保存 roundId、useId、deviceId、贴片信息快照、启用时间、归属状态和有效性。

元数据只属于前一轮。它不属于整个文件，也不属于下一轮。summarize 原行保持不变。

未关联轮次写 useId=null、patch=null。已关联但超期时保留 useId，并写 EXPIRED。没有 summarize 的尾轮不补造收尾。

完整示例见[带贴片信息的回放文件](./附件/2026-10-06-PATCH_META格式示例.txt)。演示贴片字段已标为 exampleOnly；传感器原始行来自真实样例。

### 6.3 保存顺序

```text
蓝牙字节 → 现有解析与校验 → 轮次组装
       → 绑定恢复或首次确认 → 本地归档 → 标注导出
```

先保存 RECEIVED/cgm/{sessionId}.txt。再在事务中保存轮次、绑定快照和同步事件。最后生成 OUTGOING/cgm/{sessionId}.annotated.txt。

原始文件保留。导出失败时，用原始文件和数据库重建。文件通过临时文件写完后替换，避免半行 JSON。

本期继续关闭自动删除缓存。归档失败不得删除设备数据。

## 7. 合入 migratedev

| 接入点 | 工作 |
|---|---|
| CGM 页面 | 增加贴片卡、扫码子页和轮次确认 |
| RootWorkflow | 同时传递 userId 与 deviceId |
| PatchTranslation / PatchDecision | 管理启用、换片、确认和到期 |
| PatchPortAdapter | 校验码包；读写本地表 |
| CgmParsePipeline | 读取 LOG 与 summarize 字段，识别 PATCH_META |
| CacheValidators | 保留点数校验，跳过元数据行 |

| SQLDelight / SqlStore | 新增表、查询、事务和迁移 |
| AuthDecision / AuthPortAdapter | 分开本地采集身份与远端认证 |
| AppGraph | 挂载贴片、归档和同步端口 |

scannerlibrary 固定使用 DATA_MATRIX，并读取 rawBytes。migratedev 增加依赖、相机权限和运行时授权。

连续两帧确认只用于稳定解码。标签复用由数据库判断。进入确认页后停止扫描，并忽略旧回调。

当前扫码框仅绘图。本期画面只放一码。多码场景上线前增加位置筛选。

## 8. 实施与验收

先完成本地闭环：打印 → 扫码 → 启用 → 轮次确认 → 数据归档 → 导出。

再接服务端同步。最后接量产固件。三个阶段使用相同贴片与使用周期模型。

量产固件在每轮 summarize 后返回：

```text
PATCH_REF:<measurementId>,<useId>
```

measurementId 在采集时生成，重复回放不变。固件保存 useId。设备重启不得生成新周期。绑定 ACK 必须返回实际保存的 useId。

验收必须覆盖：

- 过期片、已用片和不兼容型号被拒绝。
- 一枚贴片可以归档多轮测量。
- 重复回放恢复原绑定。
- 旧缓存不会自动归给新片。
- 未完成尾轮不变成完整结果。
- 重启和重连不延长有效期。
- 已验证账号可脱机操作。
- 写入失败可恢复，原始数据不丢失。

SQL 约束与导出附件已完成检查。App、固件和实物扫码验收尚未执行。
