# 贴片编码协议 V1

日期：2026-10-06。状态：接入规格，尚未安装到 App。

## 1. 数据包

使用私有 Data Matrix ECC 200。印刷工具采用 Base256，写入原始字节。扫码适配器读取 ScanResult.rawBytes。

```text
Header[8] + Payload[TLV] + Signature[64]
```

| Header 字段 | 长度 | 规则 |
|---|---|---|
| magic | 2 字节 | ASCII CG |
| version | 1 字节 | V1 为 1 |
| flags | 1 字节 | V1 为 0，负载未加密 |
| keyId | 2 字节 | 厂商验签公钥编号 |
| payloadLength | 2 字节 | Payload 的实际字节数 |

多字节整数使用大端序。未知主版本、非零 flags、长度不符和超长包均拒绝启用。

## 2. Payload

每个 TLV 由一字节字段编号、一字节长度和字段内容组成。

| 编号 | 字段 | 长度与编码 |
|---|---|---|
| 01 | patchId | UUID，16 字节 |
| 02 | modelId | 无符号整数，2 字节 |
| 03 | lotNo | ASCII，1～16 字节 |
| 04 | manufacturedOn | 距 2020-01-01 的天数，2 字节 |
| 05 | expiresOn | 同上，2 字节 |
| 06 | maxUseMinutes | 正整数，2 字节 |
| 07 | calibrationRef | ASCII，1～16 字节 |

字段 01～07 必须各出现一次。按编号升序写入。禁止重复编号。生产日期不得晚于有效期。使用时长必须大于零。

08～7F 为可选扩展。旧 App 保留原始字段，可跳过不认识的字段。

80～FF 为关键扩展。旧 App 不认识时拒绝启用。

已有编号不得改义。需要改变已有字段类型时，升级主版本。

## 3. 厂商签名

Signature 使用 64 字节 RAW Ed25519 签名。签名对象为 Header 与原始 Payload 的拼接，不包含 Tink 输出前缀。

生产签发工具持有私钥。App 只持有验签公钥。keyId 选择公钥；Header 本身也在签名范围内。

App 先检查包长，再检查头部，再验签，最后校验字段。验签失败不能建立使用周期。

基础包最长 142 字节。V1 总包上限为 160 字节。禁止截断字段。

签名验证来源和内容完整性，不提供保密。V1 不印用户信息、血糖记录或校准系数。后续需要保密负载时，用新 flags 定义加密协议。

参考：[Tink 数字签名](https://developers.google.com/tink/digital-signature)。

## 4. 期限规则

库存期限取 expiresOn 当日结束时间。国内产品日期按 Asia/Shanghai 解释。App 持久化时间戳时使用 UTC 毫秒。

启用后截止时间：

```text
expiresAt = min(库存期限, activatedAt + maxUseMinutes × 60_000)
```

这是本方案的保守产品规则。期限值由生产放行记录提供。App 不编造贴片寿命。

已启用贴片的 activatedAt 不可修改。重扫、重连和重启不得延期。

## 5. 印刷输入

首轮固定为：600 dpi、每模块 6 个打印点、四周 2X 白边、16×16 mm 码区、哑光白底黑码。

这是打样输入，不是已确认的最小尺寸。供应商必须用最长码包打印，并在真实贴片与目标手机上通过回读。

包装副本码与贴片码使用相同 patchId。它表示同一件产品，不表示第二枚可用贴片。
